# 网页采集链接的重写追踪

页面归档宿主通过TypeScript包把已解析节点树中的按WHATWG URL规则解释的相对资源链接改写为本地归档路径。每节点有唯一ID、标签及属性，调用方提供最终响应URL、按URI精确匹配的资源清单和允许改写的标签属性对；使用深度优先文档顺序遇到的首个base节点的href作为全页解析基准，base若非法或解析后不是HTTP/HTTPS则整页失败，后续base忽略。资源引用先相对基准解析，去片段后查清单，命中后替换为清单本地路径并原样附回片段，未命中保留原值并记录绝对URI；data:与仅片段引用保持原值且不记未命中。清单本地路径必须是无点段的相对路径，拒绝绝对路径及反斜杠；任何待处理非法URI使整页不返回改写结果。输出不可变新树及每项替换的节点ID、属性和原值。测试base在资源之后、片段、空href、重复资源和失败不修改原树。

## 包结构

- `src/types.ts`：输入输出类型定义。
- `src/rewrite.ts`：核心实现，导出 `rewriteArchiveLinks` 与 `ArchiveRewriteError`。
- `index.ts`：包入口，统一导出公共 API 与类型。
- `test/rewrite.test.ts`：基于 `node:test` 的行为测试。

## 行为约定

- **解析基准**：深度优先文档顺序找到的首个带 `href` 的 `base` 节点生效；
  其 `href` 非法或解析后协议不是 `http:`/`https:` 时抛出 `ArchiveRewriteError`，
  后续 `base` 节点一律忽略；无有效 base 时使用最终响应 URL。
- **引用处理**：仅处理允许的标签属性对。`data:` 与以 `#` 开头的仅片段引用
  保持原值，不查清单也不记未命中；其余引用按 WHATWG URL 相对基准解析，
  去掉片段后与清单 URI 精确匹配。
- **命中替换**：属性值替换为清单 `localPath`，并把原片段（含空片段 `#`）
  原样附回；每次替换记录节点 ID、属性名与原始值。
- **未命中**：属性保留原值，并按文档顺序记录去片段后的绝对 URI，
  每个未命中引用各记一条（重复引用重复记录）。
- **清单校验**：`localPath` 必须非空、相对、不含反斜杠且无 `.`/`..` 或
  空路径段；`uri` 必须是合法 HTTP/HTTPS URI。
- **失败语义**：任何非法输入（响应 URL、base、待处理 URI、清单条目、
  重复节点 ID）都在构造新树前抛出错误，输入树保持不变，且无部分结果返回。
- **不可变输出**：返回的新树、替换记录与未命中清单均递归冻结。

## 构建与测试

```bash
npm test   # 先 tsc 编译到 dist/，再用 node:test 运行 dist/test 下的测试
```

当前环境的 Node 为 Debian 构建版，未内置 TypeScript 类型擦除，因此测试脚本
通过系统 `tsc` 先编译再执行。类型声明通过指向系统全局包目录的
`node_modules` 软链解析（该目录已在 `.gitignore` 中忽略）。
