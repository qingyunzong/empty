# 版本数据压缩的快照保留边界

LSM压缩会删除旧版本，却必须保留存活快照的读结果。可导入的Go压缩包供存储宿主导入，输入按键升序、版本降序的记录，值可为删除墓碑，重复键版本内容不同拒绝；给定全部仍需支持的快照版本集合，查询在每键取版本不大于快照的首条，墓碑表示不存在。输出最少保留原记录集合，使所有指定快照逐键结果不变，未被读取的墓碑可省略但不得令旧值复活。相同可见值允许由不同原版本证明，平局取版本较新记录。用小版本全子集穷举核验最少性。

## 用法

```go
records := []dataeng.Record{
	 dataeng.Put("k", 10, []byte("v10")),
	 dataeng.Delete("k", 8),
	 dataeng.Put("k", 6, []byte("v6")),
}

retained, err := dataeng.Compact(records, []dataeng.Snapshot{6, 8, 10})
if err != nil {
	 // 输入顺序错误，或同键同版本出现不同内容。
}
```

`Compact` 按输入顺序返回最少保留记录；`KeepIndices` 返回这些记录在输入中的下标，便于宿主直接删除无需保留的条目。输入不会被修改。

## 约束与最小性

- `Record` 按 `Key` 升序排列，同键内 `Version` 降序排列。
- 同键同版本允许完全相同的重复记录；内容不同时返回 `ErrConflict`。
- 快照可重复且无需有序，内部会排序去重。
- 每个键独立压缩，全局最少记录数为各键最少保留数之和。
- 可见值相同的连续答案段只保留一条证明记录，并取仍能覆盖整段、且版本最新的原记录（即该段最后一个被读取的组记录）。
- 最老的一段“不存在”答案若下方已无必须保留的记录，可以整体省略墓碑，因为此时读取本来就取不到任何记录。

`compact_test.go` 对小版本、全部墓碑/值组合及全部快照子集枚举所有记录子集，逐例核验保留数达到下界并检查平局选择。
