# opctx — 操作上下文库

仅依赖 Go 标准库的操作上下文（cancellation tree）实现。

## 语义

- **截止继承与收紧**：子节点继承父节点的有效截止时刻；`WithDeadline`
  只能将其收紧（有效值取祖先链上的最小值）。仅当自身截止严格早于父
  有效截止时才武装自己的定时器，否则取消与原因（`Canceled` /
  `DeadlineExceeded`）由父节点传播而来。
- **父取消传播一次**：`CancelFunc` 幂等，父取消沿子树快照恰好传播
  一次；取消后新挂载的子节点立即以相同原因取消，不会漏传播。
- **子取消不影响兄弟**：取消只沿子树向下，兄弟与祖先不可达。
- **回调不漏调且唯一**：`OnCancel` 注册的回调在取消时恰好调用一次；
  若注册时上下文已取消，则同步内联调用，注册与取消竞速不会漏调；
  返回的注销函数幂等，注销后回调保证不再触发。
- **释放**：`Release` 停止截止定时器、丢弃回调（不调用）、并从父
  节点摘离，但不取消节点；子节点保留自身定时器。整树释放后时钟上
  不再残留任何定时器。

## 虚拟时间

`VirtualClock` 支持 `Advance` / `AdvanceTo` 手动推进，事件按
（时刻， 注册序）确定性同步触发，`Pending()` 报告未触发定时器数量，
用于穷举测试与资源泄漏核对。

## 测试

- `context_test.go`：截止收紧、传播唯一性、兄弟隔离、迟注册回调、
  注销、释放语义，以及 300 轮「注册 vs 取消」并发竞速（`-race` 通过）。
- `exhaustive_test.go`：虚拟时间上穷举 4 节点全部树形（6 种）×
  截止分配（3⁴ 种）× 动作（超时自然触发 / 在 5s、15s 对每个节点
  cancel 或 release），共 8262 个场景，逐节点对照独立模型核对
  最早截止、取消原因、回调唯一性与 `Done` 一致性。
