离线渲染宿主需要C++分块透明合成组件，每片元给像素、深度、稳定图元ID及预乘RGBA，按深度从后到前、同深度按图元ID合成。输入批次可任意乱序且内存只容纳有限片元，允许调用方提供暂存段接口；同ID同像素重复须去重，异内容冲突使该帧失败。只在整帧完成后发布图像，用全量排序参考验证不同批次与内存预算结果位级一致，覆盖完全透明、超量片元及暂存读取失败。

## 组件：`tc::FrameCompositor`

公共接口见 `include/tc/compositor.hpp`，实现见 `src/compositor.cpp`。

### 帧生命周期

1. `beginFrame()`：复位全部分块与暂存段，开始新一帧。
2. `pushBatch(fragments, count)`：可多次调用，批次允许任意乱序。
3. `completeFrame()`：读回暂存、分块排序并合成；仅成功时发布图像。

失败（冲突/暂存错误/非法参数）会令整帧进入失败态并拒绝发布，
`publishedImage()` 保留上一次成功帧的图像。

### 分块与有限内存

- 画布按 `tileSize` 划分为二维分块，片元按像素坐标路由到所属分块。
- 每块常驻容量为 `max(1, memoryBudgetFragments / 分块数)`；
  超出的片元顺序溢出到该块的 `IScratchSegment`，收尾时按索引读回。
- 调用方可实现 `IScratchFactory`/`IScratchSegment` 接入磁盘或共享内存
  暂存；缺省使用进程内存实现。
- 每块维护去重索引（64 位键 + FNV-1a 内容指纹 + 常驻/溢出位置），
  常驻片元数量严格受容量约束。

### 去重与冲突

去重键为 `(像素 x, 像素 y, 图元 ID)`：

- 键相同且全部字段一致：重复片元直接丢弃。
- 键相同但任一字段（深度或 RGBA）不同：返回 `Status::Conflict`，整帧失败。

### 合成顺序与位级确定性

每个分块内按 `(像素 y, 像素 x, 深度降序, 图元 ID 升序)` 排序，
逐像素从透明黑开始做预乘 alpha over：

```
out = src + dst * (255 - src.a) / 255   （整数四舍五入，逐通道）
```

排序与 over 算子不依赖输入批次顺序或内存预算，参考实现与分块实现
共用同一 `tc::premultipliedOver`，因此不同批次切分与内存预算下结果
位级一致（测试以 `memcmp` 校验 RGBA 缓冲）。

### 测试

`tests/test_compositor.cpp` 为自包含测试程序，覆盖：

- 显式深度/同深度图元 ID 顺序，乱序多批次推送；
- 全量排序参考 vs. 分块实现，跨 5 档内存预算 × 3 档批次大小位级比对；
- 同片元重复去重、异内容冲突使整帧失败且不发布；
- 完全透明帧（全零输出、透明片元不改变不透明结果）；
- 超量片元/预算 0 全量经暂存周转；
- 暂存写入失败、读取失败（收尾阶段报错）及失败后复位恢复；
- 发布门控：未完成/失败不发布，失败保留上一帧图像；
- 非法参数：零尺寸、越界像素、NaN 深度。
