# mvsg — 多版本历史可串行化分析器

分析 CLI 输入的多版本读写历史（至多 12 个事务），构造依赖图并判断是否可串行化。

## 输入格式

历史由空白/逗号分隔的操作令牌组成：

- `W<i>(<item>)`：事务 T<i> 写数据项，产生版本 `<item><i>`（版本号 = 写者事务 ID）
- `R<i>(<item><v>)`：事务 T<i> 读取版本 `<item><v>`

约束：事务数 ≤ 12；读的版本必须此前已被写入；同一事务对同一数据项只写一次；
事务写过某数据项后，再读该项只能读到自己的版本（自己的写对自己可见）。

## 用法

```sh
go run . 'W1(x) W3(y) R1(y3) R2(x1) W3(x)'   # 或 go build -o mvsg . && ./mvsg '...'
echo 'W2(x) W1(y) R3(y1) R3(x2)' | go run .  # 也支持标准输入
```

退出码：0 = 可串行化，1 = 不可串行化，2 = 输入错误。

## 判定方法

- **依赖图**：版本序取历史中写操作的先后。对每条读 `Rk(x_j)`：
  - WR 边 `Tj -> Tk`（j≠k）：写者必须先于读者，版本才可用；
  - RW 边 `Tk -> Tw`：若 x_w 在版本序中晚于 x_j（w≠j,k），读者必须先于 Tw，
    否则更新版本会遮蔽 x_j。
  更旧的版本不会遮蔽读到的版本，故不加 WW 边——这使"无环 ⟺ 存在有效串行序"
  在重放语义（读到的版本 = 版本序下最新已写版本）下严格成立。
- **环**：Tarjan 强连通分量 + 分量内 DFS 还原一条具体冲突边链输出。
- **拓扑序**：Kahn 算法，每轮从入度为 0 的候选中选 ID 最小者。
- **重放验证**：独立模拟拓扑串行序（不依赖图逻辑），逐读核对版本。
- **排列枚举对照**：事务数 ≤ 8 时枚举全部排列重放，验证
  "图无环 ⟺ 存在有效串行序" 两种判定一致。

## 测试

```sh
go test ./...
```

包含针对解析、边构造、环链、拓扑序、重放的单元测试，以及 5000 条随机小历史
（2–6 事务）上"图判定 ⟺ 排列枚举"一致性的属性测试。

仅使用 Go 标准库。
