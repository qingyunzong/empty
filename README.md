媒体服务需要Go分片提交组件，音视频各自输入带DTS、PTS、时长及轨道时间基的样本，DTS按轨道递增但PTS可回退。切点由视频关键帧给出，各轨样本按DTS所属的左闭右开区间分片；时间比较必须精确，不能先换算成毫秒。只有各轨水位都越过片尾才通过调用方落点原子发布，结束标记解除最后等待。测试不同时间基、B帧、关键帧前音频缺口与单轨延迟，不生成伪造样本补齐。

## 实现

- `rational.go`：`cmpRational` 用 `math/big.Int` 对轨道时间基做交叉相乘的精确
  有理比较，全程不换算毫秒、浮点或公共刻度，避免长内容 tick 乘积溢出与舍入跨界。
- `submitter.go`：`Submitter` 接收并发 `Push`。视频关键帧 DTS 注册切点，样本仅按
  DTS 归入左闭右开区间；PTS（含 B 帧回退）原样保留。每轨维护 DTS 水位，只有所有
  轨道水位都越过某分片右边界，该分片才通过调用方传入的 `Sink` 原子、有序发布。
- 缺口不补齐：某轨在某区间没有样本时发布空切片，绝不伪造样本。
- `EndTrack` 标记单轨结束；可选 `End` 片尾以各轨自身时间基精确校验，全部轨道结束
  后冲刷末片并解除 `Wait` 的最后等待。`Sink` 返回错误即中止整个流水线。

## 验证

```sh
go test ./... -race -count=3
```

覆盖：不同时间基（48kHz/90kHz 含恰在切点与毫秒同值反例）、B 帧 PTS 回退、关键帧前
音频缺口、单轨延迟导致的封片等待、末片结束标记、并发 race、sink 失败原子中止、
DTS 回退与片尾未达等错误路径。
