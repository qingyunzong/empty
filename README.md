# sync-plan-cli

同步规划 CLI：按接收方已有区间与包覆盖区间，选出**总字节最少**的包集合覆盖缺口
（至多 `maxPackages` 包，默认 20），再为所选包生成**峰值内存最小**的下载/解码/释放
顺序，并输出可核对的覆盖证书与调度证书。仅使用 TypeScript + Node.js 内置模块。

## 运行

```sh
npm test                                  # 构建并运行全部测试
node dist/src/cli.js examples/sample.json # 打印摘要
node dist/src/cli.js examples/sample.json -o cert.json  # 同时写出 JSON 证书
```

输入格式见 `examples/sample.json`：区间为闭区间整数段；`existing` 是接收方已有区间；
每个包有 `cover`、`bytes`（下载字节，费用）、`dict`（解码字典，占暂存）、`deps`
（解码时其字典必须驻留的依赖包）。退出码：0 正常；1 覆盖不可行或峰值超内存上限；
3 内置核对不一致（不应发生）。

## 模型与假设

- **缺口** = （所有包覆盖区间的并） − （已有区间），保证可被覆盖；唯一不可行
  来源是包数上限。
- **同覆盖包不可拆**：覆盖区间完全相同的包被捆成一个 bundle，整体选或整体不选，
  费用/字典为成员之和；调度时也是一个原子单元。
- **费用只计一次**：包覆盖可重叠，选中即付全部字节，重叠不再付费。
- **调度模型**：下载后立即解码是最优的（持有未解码字节纯属浪费），字典在所有
  依赖它的包解码完成后立即释放（提前释放不会变差）。因此调度等价于依赖 DAG 的
  拓扑序，解码包 p 时内存为 `resident(S) + bytes[p] + dict[p]`，其中 `resident(S)`
  是已解码但仍被未解码包依赖的字典之和。
- 依赖闭包：覆盖优化后，所选包的依赖若未入选会被自动补入（费用同样只计一次），
  并在证书 `dependencyClosure` 中单独列出。

## 算法

- **覆盖**（`src/cover.ts`）：把缺口在所有包边界处切成基本段；每包覆盖连续段区间，
  前缀 DP `f[t][c]` = 用 ≤c 个包覆盖前 t 段的最少字节，精确最优；并列时取包数更少。
  小实例（≤24 bundle）用子集枚举暴力核对。
- **调度**（`src/schedule.ts`）：子集 DP `dp[S]` = 恰好解码集合 S 的最小峰值，
  转移 `max(dp[S\p], resident(S\p) + bytes[p] + dict[p])`，精确最优（n ≤ 24）。
  下界 = `max_p (bytes[p] + dict[p] + Σ deps 字典)`（解码 p 时这些必须同时驻留）；
  上界 = `Σ dict + max bytes`（单下载在飞）。小实例（≤10）枚举全部拓扑序逐事件
  仿真穷举对照。

## 证书

JSON 证书包含：缺口与分段、所选 bundle 及成员、总字节与包数、依赖闭包、
逐步内存事件（下载后/峰值/解码后/释放后、释放列表）、峰值与上下界、内存上限
判定，以及 `verification` 节（暴力枚举与穷举状态图是否和 DP 一致）。
