# csp_persist

约束求解库 + CLI：冲突 Nogood（不可行赋值子句）的追加写日志持久化与崩溃恢复。纯 Python 3.11 标准库实现，单机离线，无外部依赖。

## 日志格式

每条 Nogood 以追加写（append-only）方式落盘，单条记录布局（整数均为大端）：

```
+--------------------+-----------------------+-------------------+
| payload 长度 u32   | 子句 JSON payload     | CRC32(payload) u32|
+--------------------+-----------------------+-------------------+
```

单条写入在 `flush` + `fsync` 完成后才视为已提交。

## 故障点与恢复语义

- **故障点 a：写入中途崩溃** —— 末尾条目截断（长度头、payload 或校验和不完整），视为未提交。
- **故障点 b：内容损坏** —— 存储的 CRC32 与 payload 实际校验和不匹配。

恢复时从日志头部顺序解析，遇到**第一个**截断或校验失败的条目立即停止，仅返回此前已提交的合法条目。日志不存在或为空时加载结果为空列表 `[]`，不影响正常求解。

加载后的合法 Nogood 通过 `CSPSolver.add_nogoods` 直接进入求解器子句库（按规范形式去重，不重复推导），回溯搜索时凡部分赋值覆盖某条 Nogood 的全部文字即剪枝。

## CLI

```bash
python -m csp_persist write --log <日志路径> --clause '<子句JSON>'
python -m csp_persist load  --log <日志路径>
```

- `write` 成功输出 `{"status": "committed", ...}`，退出码 0。
- `load` 输出加载到的子句列表（JSON 数组）。
- 退出码：`0` 成功；`1` 日志路径不可写等 I/O 错误；`2` 子句 JSON 非法。

子句格式：非空 JSON 数组，每个元素为恰好含 `var`（非空字符串）与 `value`（JSON 标量）的对象，如 `[{"var":"x","value":1}]`。

持久化失败（如只读目录）不会抛出致命错误，内存中的搜索逻辑不受影响（`CSPSolver.persist_nogood` 返回 `False`）。

## 测试

```bash
python -m unittest discover -v
```

测试覆盖：3 条 Nogood 写入/加载往返与剪枝行为、第 2 条截断崩溃恢复、篡改 1 字节导致校验失败、只读目录写入失败但求解正常、缺失/空日志、非法子句退出码，以及与朴素参考解析器（`tests/test_persist.py` 中独立实现的 `naive_parse`）的随机对照。真实运行结果见 `result.txt`。
