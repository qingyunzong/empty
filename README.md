# quorumcli — 故障域感知的仲裁集选择 CLI

仅使用 Go 标准库。输入节点的故障域、权重与成本，求解两类仲裁问题并输出 JSON 证书。

## 构建与测试

```sh
go build -o quorumcli .
go test ./...
```

## 输入格式

JSON 文件（`-input`，或 `-` 读标准库 stdin），`nodes` 数组或裸数组均可：

```json
{"nodes": [{"id": "n1", "domain": "zone-a", "weight": 3, "cost": 5}, ...]}
```

每个节点有唯一 `id`、故障域 `domain`、投票权重 `weight`（≥0）与选取成本 `cost`（≥0）。最多 64 个节点、64 个域（子集以 uint64 位掩码表示）。

## 子命令

### `quorum` — 最小成本合法仲裁集

```sh
quorumcli quorum -input examples/cluster.json -max-size 22 -min-domains 2 -verify
```

合法集要求：总权重严格过半（`2*weight > totalWeight`）、覆盖至少
`-min-domains` 个不同故障域、至多 `-max-size` 个节点（默认 22）。输出成本最小的合法集，
证书包含节点列表、权重/总权重、是否过半、域列表/域数、成本与规模。

### `pair` — 读写仲裁集对

```sh
quorumcli pair -input examples/cluster.json -max-size 18 -min-domains 2 -verify
```

选取一对**不同**的读、写仲裁集 R、W，故障模型为单节点故障（故障节点取自 R ∪ W），要求：

- 每个仲裁集在任意允许单故障后仍合法（权重过半、域数达标）——即 R、W 都是容错仲裁集；
- 任意允许单故障后两者仍相交，等价于 `|R ∩ W| ≥ 2`；
- 每个集合至多 `-max-size` 个节点（默认 18）；
- 目标：最小化并集成本 `cost(R ∪ W)`。

输出包括：读/写仲裁集证书、并集节点与并集成本、最优下界（搜索前证明的下界 =
最便宜容错仲裁集成本）与上界（= 最优并集成本）、`provedOptimal`、搜索统计，
以及**每个故障场景的交集证书**（无故障场景 + R∪W 中每个节点故障各一条：
幸存交集节点、读/写集合的权重与域数、是否仍合法、是否仍相交）。

### 公共标志

- `-verify`：小规模全枚举验收。`quorum` 对全部 2^n 子集枚举（n ≤ 24），
  `pair` 枚举全部容错仲裁集及其全部配对（n ≤ 18），与求解器结果比对，
  输出 `verification.match`。
- `-max-steps N`：分支限界步数预算（默认 0 = 不限）。预算耗尽时输出当前最优解，
  `provedOptimal: false`，上下界仍然有效（下界可能退化为最便宜合法仲裁集成本）。

## 算法

- 子集搜索为分支限界：节点按有效成本/权重比排序，贪心前缀产生初始上界；
  剪枝包括：top-k 后缀权重和（基数约束下的权重上界）、后缀域并集、
  分数背包（LP 松弛）成本下界。
- 容错判定增量完成：递归中维护各域成员计数，叶子处 O(1) 判定
  （权重 − 最重成员 ≥ 多数阈值；存在单节点域时域数需 ≥ minDomains+1）。
- `pair` 先求最便宜容错仲裁集得下界，再以为其定价"额外成本"的伙伴搜索得启发式上界，
  随后单趟枚举容错仲裁集并与已见集合配对，用当前最优并集成本动态收紧枚举上界。

## 测试

`go test ./...` 覆盖：合法性/容错性单元测试、输入校验、已知答案样例、
不可行判定、随机实例上求解器与全枚举的对拍（单仲裁 40 种子 × n≤14，
对偶 30 种子 × n≤11）、容错枚举与暴力枚举一致性、故障场景证书有效性、
以及排序错位回归样例。
