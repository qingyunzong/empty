# 采集查询替换的包含见证与反例

采集查询规划器要判断一次查询替换会不会漏数据，请用Go交付供规划器导入的合取查询包含包，输入已经解析的查询结构，不解析SQL。关系模式给出关系名及正整数元数，数据库和查询均为集合语义，无NULL、算术、否定、聚合或隐含键约束。查询含有序头项和关系原子合取，项是有明确标签的变量或UTF8常量，常量按字节相等，变量作用域只属于所在查询；头变量必须出现在体内，允许重复头项、重复原子、自连接及零元头。每查询最多12变量、20原子，同名关系元数必须一致。检查A包含于B表示对所有有限数据库A(D)均为B(D)子集；两头长度必须相等。搜索从B的变量到A体中出现的变量及两查询全部常量的映射，常量固定，映射后B每个体原子须在A体中，B头须逐项等于A头。返回包含时给完整映射，不能把反方向映射当证明；不存在映射则生成反例：把A每个变量替换成与所有用户常量互异的带类型新符号，将A体作为数据库并返回A头元组，同时用实际查询解释器核实该元组属于A且不属于B。空体只允许常量头，空体查询产生一个头元组，数据库中未列关系为空；反例新符号不能通过拼接可碰撞的普通字符串实现。允许一次调用限制最多尝试多少个完整或部分变量赋值并暂停，预算耗尽返回未决和可继续的搜索游标，不能返回不包含；同一输入连续恢复应等价于足够预算一次运行，游标不得引用调用方可修改的对象。变量按UTF8名字节序、候选项按常量在先再变量且各自字节序搜索，始终返回首个成功映射；每次为下一个变量试一个候选计一步，已知头约束和部分原子可用于剪枝但不能跳过可能更早的成功映射。完成后可双向判断等价，但不能只在调用方提供的样例数据上推断包含。提供规划器调用示例及独立小数据库穷举测试，包含A(x):-R(x),S(x)与B(x):-R(x)、反向失败的最小构造、自连接中变量合并、常量固定、重复头位置不一致、空体及分段预算恢复；反例必须由解释器重算，不仅检查证书字段。
