# policy-store

不可变版本化策略库：批量增删规则生成带前后摘要的差分，逆发布先核后像，
策略热更与读者快照隔离，任何历史版本都不会被修改。
仅使用 TypeScript + Node.js 内置库（`node:crypto`、`node:test`、`node:assert`），零外部依赖。

## 设计

- `src/rules.ts` — 规则（`id` / `decision` 决议 / `source` 来源 / `pattern`）与版本摘要
  （规则数、决议分布、来源分布、对排序规范化记录计算的 SHA-256）。
- `src/diff.ts` — 差分（携带 `before` / `after` 摘要与增删规则集）、逆差分、相邻差分复合。
- `src/store.ts` —
  - `plan(batch)`：对当前版本校验并生成带前后摘要的差分（同批内先增后删自动抵消）；
  - `publish(diff)`：**先核**（`before` 摘要须匹配当前版本，否则抛 `DiffVerificationError`，
    不产生任何新版本）**后像**（在全新 Map 上落地，落地结果再与 `after` 摘要核对）；
  - `unpublish(diff)`：逆发布 = 逆差分 + 同样的先核后像，以追加新版本的方式回到旧像，
    历史版本永不改写；
  - `snapshot()`：读者快照钉住某一不可变版本，热更对读者完全不可见；
  - 版本规则表对外只暴露冻结的只读视图，规则对象逐个 `Object.freeze`。

## 测试

`npm test`（先 `tsc` 编译，再跑 `node --test`）。覆盖：

1. 批量增删生成带前后摘要的差分；
2. 先核后像：前像摘要不符或后像被篡改均拒绝且库状态不变；
3. 历史版本不被后续发布改变（只读视图写入抛错）；
4. 策略热更与读者快照隔离；
5. 随机化核对（种子 20261005）：60 轮随机批次发布，300 次随机区间差分复合
   核对前后摘要与落地像，再逆序逆放全部差分，决议与来源分布完全恢复为空库；
6. 逆放顺序错误时先核失败、库状态不变；
7. 差分复合要求相邻、逆差分前后摘要互换。
