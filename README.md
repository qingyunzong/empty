# 采集响应里的域名压缩指针

采集器收到的响应里，域名后半段常用指针指回前面的标签，指针若指向尚未解析的字节或绕回自身，后面的资源记录都会错位。实现可导入的Go包，供采集器调用，只解析本题消息，不访问网络。头部12字节都是大端：uint16标识、uint16标志、以及问题、回答、权威、附加四段的uint16数量。标志的最高位必须为1，其余位原样返回。四段按这个顺序排列。问题含名字、uint16类型和uint16类。资源记录含名字、uint16类型、uint16类、uint32 TTL、uint16数据长度和正好这么多数据字节。名字由标签组成，首字节为0时结束。首字节1至63表示随后这么多原始字节，标签内容不作文本解码。首字节高两位为11时，这是两字节指针，低14位是从消息起点计算的偏移；高两位为01或10都失败。指针必须是该名字在线上的结尾，后面不能再接标签。指针目标必须严格小于指针自身起点，且正好落在此前已经出现过的标签起点或名字结束字节上，不能落到标签内容中间，也不能越出消息。沿指针还原时，重复进入同一偏移，或跳转超过16次，都失败。还原后的标签之间用点连接，根名字是空串，总字节不超过255。数据部分默认保持原始字节，不跟随其中的指针。只有类型1、28和15例外：类型1必须是4字节，类型28必须是16字节，类型15是大端uint16优先级后再接一个可含指针的名字。数据长度大于宿主maxRdata，或消息总长大于maxMessage时，一旦该长度已知就拒绝，不按声明分配。四段数量必须正好被实际记录用尽，消息不能剩余字节，也不能在记录中间结束。Push在消息尚未完整时保留前缀；Finish时仍不完整则失败。任一失败不交付半条消息，组件停止。测试独立构造指针，覆盖环、指向更后面的偏移、落到标签内容中间、MX名字、地址长度不符、根名字、数量与字节不符，以及头部被切到下一块。期望记录不得调用被测包生成。
