# chansim

通道模拟库：有缓冲收发 + 确定性 select，仅依赖 Go 标准库。

## 语义

- `New(cap)` 创建容量为 `cap` 的通道，`cap == 0` 为无缓冲（会合）通道。
- `ch.Send(v) bool`：阻塞直到值被接收或入缓冲；通道关闭后返回 `false`（不 panic）。
- `ch.Recv() (any, bool)`：阻塞直到有值；关闭后先排空缓冲，再返回零值 `nil, false`。
- `ch.Close()`：关闭通道，幂等。阻塞的发送者全部失败，阻塞的接收者拿到零值。
- `Select(cases ...Case) (idx, val, ok)`：分支由 `Send(ch, v)` / `Recv(ch)` 构造。
  - 多个分支同时就绪时，**选择下标最小的分支**（确定性，非 Go 的随机选择）。
  - 一次选择只提交一个分支；其余分支的登记在提交时**全部撤销**，
    落选的发送值绝不会在之后被送达（无幽灵发送）。
  - 发送分支的 `ok` 表示是否发出（遇关闭为 `false`）；接收分支的 `ok=false`
    表示通道已关闭且缓冲已排空。

## 实现

单个全局互斥锁保护整个模拟：`Select` 的就绪检查、提交与撤销全部在锁内
原子完成。阻塞操作在每个相关通道的队列中各登记一个节点；提交时把本操作
的所有节点从队列中摘除，因此队列中只存在活跃登记。

## 测试

- `chansim_test.go`：缓冲收发、关闭后排空再零值、发送失败、select 最小
  下标优先、阻塞 select 的撤销（无幽灵发送）、会合交接、并发冒烟。
- `exhaustive_test.go`：穷举小事件。两条通道（无缓冲 + 容量 1）上取 12 种
  事件（发送/接收/关闭/四种混合 select/双收 select/双发 select），枚举所有
  长度 ≤ 5 的事件序列（248,832 条），每个事件后校验：守恒与 FIFO（每个被
  接收的 token 都来自已提交的发送，无幽灵）、队列登记与挂起操作精确一致、
  缓冲容量与阻塞不变式、失败语义。

## 实测结果

```
$ go test ./...
ok  	chansim	0.653s
$ go test -race ./...
ok  	chansim	7.440s
```

穷举深度临时提升到 6（2,985,984 条序列）同样通过（7.25s）。
