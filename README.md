# binpack-cli

装箱 CLI：将至多 20 件物品装入整数容量的箱子，满足分组与禁对约束，并按
字典序最小化目标输出规范化结果。纯 TypeScript + Node.js 内置库，零依赖。

## 问题定义

- 整数箱容量 `capacity`，物品大小为正整数，物品数 ≤ 20；
- **同组必须同箱**：`group` 相同的物品放入同一箱（组先合并为单元）；
- **禁对不能同箱**：`forbidden` 中的物品对不得同箱；
- **目标（字典序）**：先箱数最少，再使"规范负载序列"字典序最小——
  各箱按箱内最小物品 ID 排序后，负载序列逐项比较；
- **输出规范化**：箱号按最小物品 ID 编号（含全局最小 ID 的箱为 1 号箱）。

## 用法

```bash
npm run build          # 编译到 dist/
node dist/src/cli.js [--verify] [input.json]
# 未给文件时从 stdin 读取；--verify 对小实例（≤12 件）枚举所有集合划分核对
```

输入（JSON）：

```json
{
  "capacity": 10,
  "items": [{ "id": 1, "size": 4, "group": "a" }, { "id": 2, "size": 6 }],
  "forbidden": [[2, 4]]
}
```

输出（JSON，`loads`/`bins` 按规范序，`assignment` 为各物品的 1 基箱号）：

```json
{ "binCount": 3, "loads": [8, 6, 8], "bins": [[1, 3], [2], [4, 5]],
  "assignment": { "1": 1, "2": 2, "3": 1, "4": 3, "5": 3 } }
```

示例见 `examples/sample.json`。不可行时退出码 1 并输出原因到 stderr。

## 算法

1. **合并单元**：同组物品经并查集合并为单元；组内出现禁对或组总大小
   超容量直接判不可行。
2. **最少箱数 k**：单元按大小降序做带记忆化的可行性 DFS（状态为
   (负载, 冲突投影, 容量) 多重集合），从 max(⌈总大小/容量⌉, 最大团)
   起逐个尝试 k。
3. **字典序最小规范负载向量**：整箱完成 DP。单元按 minId 升序处理，
   逐箱装满——第 j 箱必含当前最小 ID 的剩余单元，故状态完全由
   (已用箱数, 剩余单元位掩码) 决定。候选子集按负载升序尝试，同负载时
   取字典序最小后缀；末箱取全部剩余。DP 值即字典序最小后缀向量。

## 测试

```bash
npm test   # tsc 编译 + node --test
```

测试内容：手工用例（组合并、字典序 tie-break、禁对、不可行、输入校验）、
400 个随机小实例与集合划分暴力枚举交叉核对（箱数与规范负载向量一致）、
60 个 20 件实例的求解与合法性检查、CLI 端到端 `--verify` 核对。

## 实际运行结果（2026-10-05, Node v22.22.1）

```
$ npm test
# tests 9
# pass 9
# fail 0
# duration_ms ~3000
```

- 9/9 测试通过；
- 额外离线核对：5000 个随机实例（n ≤ 10，含分组与禁对）与暴力枚举
  全部一致（0 例目标值失配；300 例为同目标值的等价具体装箱）；
- 性能：180 个 20 件随机实例（容量 10–30，禁对密度 0–20%）全部
  ≤ 1.1s，绝大多数 < 50ms；病态情形（20 个全同小物品）< 200ms。

依赖：Node.js ≥ 18 与 TypeScript 编译器（`npm i -g typescript` 或
`npx tsc`）。无第三方运行时依赖。
