# 整数列的补丁基值与长间隙恢复

ORC式整数列接入器遇到少量离群值，不能只按低位宽读取而丢掉补丁。给宿主开发Go可导入的单run解码包，容器已提供N、W、BW、PW、G、P及完整run字节长度，只实现这里封闭定义的patched-base体，不实现容器、RLE其他模式或编码优化。1<=N<=512，W及PW各来自集合{1..24,26,28,30,32,40,48,56,64}，1<=BW<=8，1<=G<=8，0<=P<=31，W+PW<=64且G+PW<=64；参数先校验。体先放BW个字节的大端基值，最高位表示负号，清掉该符号位后的剩余无符号数为绝对值；负号置位时取其相反数，不按BW位二补码符号扩展，负零按0接受。其后N个W位无符号低部，高位先行连续打包并补到下一字节；再接P个补丁槽，槽宽F是上述宽度集合中最小的不小于G+PW者，各槽高位先行连续打包，最后补到下一字节。每槽低PW位为patch，再往上G位为gap，若F>G+PW更高位须全0；两段末填充位也须0，声明体长须恰好，不能把下一run数据当补丁。补丁定位严格按以下规则：cursor初始0，每槽令cursor+=gap；若G=8且gap=255且patch=0，此槽只是长间隙延续，不修改任何低部，下一槽从这个cursor继续累计；其他槽patch必须非零，cursor须<N且严格大于上一个真正补丁的位置，然后把该位置低部与patch左移W位作按位OR，cursor不额外加1。首个真正补丁允许位置0；延续槽可以连用，但最后一个槽不能是延续，G<8时不允许patch=0冒充延续。低部全部读取完才处理补丁，不能把补丁槽数当异常值数，因为延续槽不对应值。每个修复后的无符号差值加上有符号基值，使用足够宽的数学整数计算，最终须落在int64范围，否则整run报数值溢出，禁止回绕；不能对低部或patch作zigzag。结果包含N个int64及每值的低部位范围、基值范围，真正打补丁值另带它的槽序号和位范围；延续槽应列在该补丁的间隙来源中，不伪造为一个数值。Push接受任意字节切块，Finish才校验体长和尾填充，单run全部通过后仅交付一次；截断、参数错误、补丁位置越界/重复、非法延续、溢出与额外字节分别可辨识，失败后不可继续Push，宿主可新建实例处理下一run。只缓存一个run所需有界低部和最多31槽，不按不可信声明任意分配。给列接入宿主调用例，独立编码构造及逐位数学整数参考；覆盖负基值符号位与二补码不同、负零、位置0、连续真补丁gap=1、255及510间隙延续、末延续无真补丁、P=0、F向上取整的空高位、修复结果恰为int64最大值、最小可表示负基值与正向越界、非字节对齐两段、真补丁位置重复或越过N以及所有切块点。测试元数据与run体由工程自行构造，不依赖外部ORC文件或库。
