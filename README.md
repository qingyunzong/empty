# rule-engine

小型正向规则引擎(Python 3.11 标准库,无第三方依赖)。

规则形如 `head :- a, b, not c`:当 `a`、`b` 为当前事实且 `c` 不是当前事实时,
推导出 `head`。

## 使用

```bash
python -m rule_engine              # 从 stdin 逐行读取命令
python -m rule_engine derive p     # 单条命令模式
```

命令(每行一条,空行与 `#` 开头的行被忽略):

| 命令 | 行为 |
| --- | --- |
| `assert <fact>` | 断言基础事实;若该事实当前是派生事实则报错,退出码 6 |
| `retract <fact>` | 撤回基础事实;对派生/未知事实为 no-op |
| `rule <head>:-<a,b,not c>` | 添加规则(语法错误退出码 2),规则 id 自增 |
| `derive <fact>` | 查询事实是否成立,打印 `yes`/`no`(单命令模式退出码 0/1) |

未知谓词允许出现,无需预先声明。

## 语义

- 事实分**基础**(assert)与**派生**(规则推出);派生事实不得被 assert。
- 每个派生事实维护全部证明 `(rule_id, 正条件集合)`;同一事实有多条证明时,
  只有全部证明失效才撤销该事实。
- `not c` 只检查当前事实集;断言可能使负条件失效从而撤销派生,
  撤回也可能使负条件成立从而触发新推导。
- 每轮推导按规则 id 升序评估、新事实按字典序加入,结果确定。
- 规则循环允许;修复循环有轮次上限,保证收敛、不会无限生成。

## 增量维护(反向依赖)

引擎维护事实 → 引用它的规则的反向依赖表(正/负条件分开)。状态变更后:

1. **删除级联(DRed)**:被断言的事实剪除受其负条件影响的证明;
   被撤回/删除的事实作为种子,沿正向证明依赖过度删除(over-delete)
   所有可能受影响的派生事实——这保证循环互相支持的证明组在失去
   良基支持后整体坍塌。
2. **饱和推导**:按确定顺序前链到不动点,重新推出仍有良基证明的事实。

两阶段交替直至稳定。只触碰反向依赖可达的事实,无关派生不受影响。

## 测试

```bash
python -m unittest discover -s tests -v
```

- `tests/test_engine.py`:验收 A(双证明撤一仍成立)、B(级联失效与再激活)、
  C(负条件断言后撤销派生)、循环收敛、解析错误等。
- `tests/test_cli.py`:命令行行为与退出码(6 / 2)。
- `tests/test_random.py`:验收 D——随机 30 事实 + 随机规则/断言/撤回序列,
  每一步与从头计算的完美模型参照(`naive_closure`)对照。
