# 应用记录的填充与结束标记

应用采集若把内容长度和填充长度加在一起跳过，长度为0的输出记录就不再是流结束。实现可导入的Go组件，供应用采集调用，不启动进程。每条记录以8字节头开始：版本必须为1，类型、大端uint16请求号、大端uint16内容长度、填充长度、保留字节必须为0。填充紧跟内容，填充字节不交付。内容长度大于宿主maxContent时在这2字节可读后拒绝，不按声明分配。只接受类型6、7和3。类型6和7的内容按原始字节交付，内容长度为0的类型6是该请求输出流的结束标记，必须交付，不能跳过。类型3的内容长度必须为8：大端uint32应用状态、1字节协议状态和3字节保留。类型3关闭该请求号，之后再出现同一请求号则失败。同一请求号的类型6和7可以交错。Push可停在内容或填充中间；Finish时记录未完成则失败。失败停止组件，已交付记录保留。测试独立组记录，覆盖填充被当成内容、长度为0的结束标记、结束后又出现类型6和头被切开。期望记录不得调用被测组件生成。

## 使用方式

```go
dec := dataeng.NewDecoder(64 * 1024)
if err := dec.Push(chunk); err != nil {
	return err
}
if err := dec.Finish(); err != nil {
	return err
}
for _, rec := range dec.Records() {
	// 类型 6/7 的 rec.Content 是原始输出字节；
	// 类型 3 的 rec.AppStatus / rec.ProtocolStatus 是关闭状态。
	_ = rec
}
```

`Push` 可在头部、内容或填充中间截断；`Records` 返回失败前已经交付的记录。
