# 采集数据的断点续传校验

下载采集服务需要可导入的Go流组件，调用方提供远端请求函数和事务暂存接口。初次响应须为200并提供强ETag与非负总长度，暂存字节和长度原子持久化。长度为零时直接校验空内容摘要，不发续传请求；否则从已持久长度发Range并携带If-Range。206须有相同强ETag及完整Content-Range，其起点等于请求起点、终点等于总长减一、总长与暂存一致，正文长度须等于区间长度；缺失或不一致则丢弃暂存并返回错误，下次调用从零请求。续传收到200时丢弃旧暂存，将该响应按初次响应规则从零处理。仅在完整长度及调用方给定SHA256均匹配后原子发布。用可控HTTP服务测试中断、实体轮换、错误区间、空文件及取消，确认不会混合不同版本。

## 组件

可导入包 `example.org/dataeng/q0006/streamdl`，调用方只需提供两个依赖：

- `Requester`：执行单次 HTTP GET 的函数，URL、鉴权、`http.Client` 均由调用方掌握；组件按需附加 `Range` 与 `If-Range` 头。
- `Staging`：事务型字节暂存接口。`Begin` 返回的 `Txn` 在 `Commit` 时把字节与长度原子落盘，失败回退到上一保存点。

包内附带两个实现：

- `FileStaging`：基于数据文件 + 原子替换元数据文件的磁盘暂存，`Commit` 先 fsync 数据再原子 rename 元数据，崩溃后只暴露已提交保存点；`Publish` 经同目录临时文件 + rename 原子发布。
- `MemStaging`：内存暂存，供测试使用，可通过 `CommitFail` 注入持久化故障验证原子性。

## 协议规则

- 初次响应必须为 200，带强 ETag（拒绝缺失、弱 ETag、畸形值）与非负 `Content-Length`。
- 总长度为零时直接校验空内容 SHA256，不发起任何续传请求。
- 非空实体从已持久长度发起 `Range: bytes=N-` 并携带 `If-Range: <强ETag>`。
- 206 必须满足：强 ETag 与暂存一致、`Content-Range` 完整且起点等于请求起点、终点等于总长减一、总长与暂存一致、正文长度等于区间长度；任一缺失或不一致即丢弃暂存并返回 `ErrProtocol`，下次调用从零请求。
- 续传收到 200 表示实体已重启，丢弃旧暂存并按初次响应规则从零处理，杜绝新旧版本字节混合。
- 连接中断或上下文取消会提交已校验前缀，供后续调用恢复；其他非预期状态码保留暂存以便重试。
- 仅当完整长度与调用方给定 SHA256 均匹配时才原子发布，摘要不符返回 `ErrDigest` 并丢弃暂存。

## 测试

测试使用进程内可控 HTTP 服务（基于内存双端连接，无需监听端口），覆盖：中断后续传、实体轮换（含等长轮换）、六类错误 206 区间、空文件、上下文取消、非续传 206、正文超长/截断、初始响应校验、文件暂存跨实例恢复与提交原子性。

运行：

```sh
go test ./... -race
```
