# dual-worker-scheduler

双人任务规划库：两名工人执行至多 14 项工作，每项工作给定技能要求、整数时长与前置依赖；
“双人任务”必须同步占用两名工人。在整数时间上限（默认 40）内求最短总工期（makespan），
并输出时间轴。仅使用 Node.js 内置模块，零运行时依赖。

## 模型

- 工人：`W1(A)`、`W2(B)`。
- 技能 `skill`：`A`（仅 W1）、`B`（仅 W2）、`any`（任一人）、`both`（两人同步占用同一区间）。
- `deps`：前置工作全部结束后才能开始；依赖图必须无环。
- 时间在离散整数格点 `0..horizon` 上推进。

## 算法

- 主求解器 `solve()`（`src/solve.ts`）：事件驱动的离散状态搜索（DFS + 分支定界）。
  状态为 `(当前时间, 已完成集合位掩码, 运行中工作及剩余时间)`；每个事件点枚举所有可行的
  开工子集（含显式空闲选择），用两个下界剪枝：剩余工时/2 与关键链（最长依赖尾链），
  并对状态做支配记忆化（同一状态以更晚时间到达则剪枝）。返回最优解或 `null`（超上限不可行）。
- 独立核对器 `bruteForceMakespan()`（`src/bruteforce.ts`）：枚举全部优先级排列，
  用串行调度生成方案（serial SGS，按依赖资格逐阶段选取）求最优工期，用于小实例交叉验证。
- `checkSchedule()`（`src/schedule.ts`）：校验排程的时长、技能、依赖顺序、工人互斥、
  双人同步与上限。

## 使用

```bash
npm test        # 编译 (tsc) 并运行全部测试
npm start       # 求解内置 14 工作演示实例并打印时间轴
npm run typecheck
```

要求：Node.js（实测 v22.22.1）与全局 `tsc`（实测 v7.0.2）。先 `tsc` 编译到 `dist/` 再运行，
因为该 Node 构建未启用类型剥离（type stripping）。

## 实测结果（2026-10-06，本机）

- `npm test`：**47 个测试全部通过**（3 个测试组，约 7.5 s）：
  - 6 个手算最优解用例（并行、依赖链、技能独占、双人同步、空闲权衡、超上限不可行）；
  - 40 个随机小实例（5–8 个工作）与全排列暴力枚举逐一核对，最优工期完全一致；
  - 1 个 14 工作演示实例的最优性与时间轴渲染。
- `npm start`（14 工作、上限 40）：**最优总工期 30**，搜索仅扩展 153 个状态，约 54 ms。

## 文件结构

- `src/model.ts` — 问题类型与校验（技能、依赖无环、≤14 工作）
- `src/solve.ts` — 最优求解器（离散状态搜索 + 分支定界）
- `src/bruteforce.ts` — 全排列 + serial SGS 独立核对器
- `src/schedule.ts` — 排程结果与合法性校验
- `src/timeline.ts` — ASCII 甘特图时间轴
- `src/demo.ts` / `src/main.ts` — 14 工作演示实例与 CLI
- `test/solver.test.ts` — 全部测试（node:test）
