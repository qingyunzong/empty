# 双人任务规划库（最短总工期）

两名工人（A/B）执行至多 **14** 项任务，每项任务给定**技能要求**、**整数时长**与**前置依赖**；
双人任务必须**同步占用两名工人**。求**最短总工期（makespan）**，整数时间上限 **40**，输出时间轴。
小实例用独立的离散状态搜索交叉核对。

仅使用 TypeScript + Node.js 内置库（`node:test` / `node:assert` / `node:fs`），无第三方运行时依赖。

## 模型

- 任务：`{ id, duration, workers, skill?, deps? }`
  - `workers: 1` 单人任务，`skill: "A" | "B" | "any"` 限定可执行工人（默认 `any`）
  - `workers: 2` 双人任务，同一时段同步占用 A、B 两人
  - `deps`：前置任务 id 列表，全部完成后本任务才可开工
- 不可抢占；时间取非负整数；总工期超过 `horizon`（默认/最大 40）判定不可行
- 输入校验：id 唯一、依赖存在、无依赖环、时长为正整数、任务数 ≤ 14

## 算法

- **精确求解**（`src/solver.ts`）：事件驱动离散状态搜索（Dijkstra，代价=时间）。
  状态 =（已完成任务位掩码，进行中任务及其结束时刻/占用工人）；
  决策点 = 任务完成事件（或 t=0）。每个空闲工人可开始一个就绪单人任务、
  两人同步开始一个双人任务，或**故意空闲**到下一事件（理论及实验均表明：
  存在“故意空闲严格更优”的实例，见测试用例 7，非延迟调度只能得到 13 而最优为 11）。
  首次弹出“全部完成”状态即为最优，沿父指针还原时间轴。
- **独立核对**（`src/brute.ts`）：逐刻（单位时间步）推进的暴力 BFS，
  每个整数时刻枚举全部开工/空闲组合，机制与主求解器完全不同，用于小实例交叉验证。
- **时间轴校验**（`checkSchedule`）：依赖先后、工人占用不重叠、双人同步、
  技能匹配、时长与上限、makespan 一致性。

## 用法

```bash
npm test                              # 编译并运行全部测试
npm start -- solve examples/demo.json # 求解并输出时间轴
node dist/src/cli.js solve 实例.json   # 求解
node dist/src/cli.js verify 实例.json  # 求解 + 与逐刻暴力搜索交叉核对
node dist/src/cli.js solve --demo      # 内置示例
```

```
  [ 3 -  5]  环境搭建         工人B

  [17 - 19]  修复回归         工人A
  [17 - 20]  文档编写         工人B
  [20 - 21]  发布评审         工人A+工人B(同步)

工人A: 0-3 空闲 | 3-7 架构设计 | 7-13 核心开发 | 13-17 联调测试 | 17-19 修复回归 | 19-20 空闲 | 20-21 发布评审
工人B: 0-3 需求分析 | 3-5 环境搭建 | 5-7 空闲 | 7-13 核心开发 | 13-17 联调测试 | 17-20 文档编写 | 20-21 发布评审

```

## 项目结构

```
src/types.ts    实例/时间轴类型定义
src/solver.ts   精确求解器（事件驱动 Dijkstra）+ 输入校验 + 时间轴校验
src/brute.ts    独立逐刻暴力搜索（交叉核对用）
src/cli.ts      命令行：求解 / 交叉核对 / 时间轴打印
test/solver.test.ts  12 个测试（node:test）
examples/demo.json   示例实例
types/node-shims.d.ts 离线环境最小 Node 类型声明
```
