# csp_persist — CSP Nogood 持久化与崩溃恢复

单机离线，仅依赖 Python 3.11 标准库。提供冲突 Nogood（不可行赋值子句）的
追加写日志持久化、崩溃恢复，以及带回溯搜索与 Nogood 剪枝的 CSP 求解器。

## 日志格式

每条记录（大端序）：

```
+-------------------+----------------------+------------------+
| payload_len (4B)  | JSON payload (N 字节) | CRC32(payload)4B |
+-------------------+----------------------+------------------+
```

子句 JSON 为字面量数组：`[["var", int], ...]`（var 为非空字符串、值
为整数、变量不重复）。单条记录完整写入并 `fsync` 后才视为已提交。

## 故障点与恢复语义

- 故障点 a：写入中途崩溃 → 尾部条目截断（头/载荷/校验和不完整）。
- 故障点 b：已提交内容被篡改 → CRC32 与载荷不匹配。
- 恢复：顺序解析日志，遇到第一个损坏/不完整条目立即停止，仅返回
  之前已提交的合法前缀；日志不存在或为空时返回空列表。
- 加载后的合法 Nogood 直接进入求解器子句库（`NogoodStore` 去重，
  不重复推导），搜索时自动剪枝。
- 持久化失败（如只读目录）以 `LogWriteError`/非零退出码报告，
  内存中的搜索逻辑不受影响。

## CLI

```bash
python -m csp_persist write --log <日志路径> --clause '[["x",1],["y",2]]'
python -m csp_persist load  --log <日志路径>
```

- `write`：追加一条子句并刷盘，输出 `{"status":"ok","committed":true,...}`。
- `load`：输出 `{"status":"ok","clauses":[...],"count":N}`。
- 退出码：`0` 成功；`2` 日志路径不可写/IO 错误；`3` 子句格式非法。

## 测试

```bash
python -m unittest discover -v
```

测试覆盖：3 条写入/加载往返与内存子句一致性、剪枝行为、第 2 条截断
仅恢复第 1 条、篡改 1 字节导致第 2 条及后续全部丢弃、只读目录写入
失败但求解正常、缺失/空日志返回空列表、非法子句非零退出码，以及与
朴素日志解析参考实现的 50 组随机对照用例。
