# patch-merge

基于原版本字节区间的三路补丁合并库（TypeScript，仅依赖 Node.js 内置模块）。

## 模型

每个分支对同一原版本给出一组编辑 `Edit { start, end, text }`，语义为
“把 `original[start:end]` 替换为 `text`”（字节/码元区间，左闭右开）：

- `start === end` → 插入
- `text === ""` → 删除
- 否则 → 替换

## 合并规则

1. 两边编辑区间不相交（含边界相邻）→ 都可合并；
2. 同点插入 → 都保留，按分支 ID 字典序排列（ID 小者在前），与传参顺序无关；
3. 区间相交但作用效果相同（如重叠删除同一批字符、完全相同的编辑）→ 应用一次；
4. 区间相交且效果不同 → 冲突，自动采用分支 ID 较小一方，并在 `conflicts` 中记录双方；
5. 删除/替换区间包含另一方的修改（含严格内部的插入点）→ 冲突；边界上的插入不冲突。

## API

```ts
import { merge } from "./src/merge.js";

const r = merge("hello world",
  { id: "a", edits: [{ start: 0, end: 0, text: ">> " }] },
  { id: "b", edits: [{ start: 6, end: 11, text: "there" }] });
// r.text === ">> hello there", r.conflicts === []
```

`MergeResult`：

- `text`：合并结果文本（冲突已按分支 ID 取舍）；
- `conflicts`：`{ start, end, lowEdits, highEdits, lowText, highText, winner, resolvedText }`；
- `segments`：keep/replace 分段，位置映射的数据基础；
- `map`：双向位置映射 `PositionMap`：
  - `origToMerged(p)`：原版本偏移 → 合并结果偏移（保留区线性映射；被替换/删除区间
    内部映射到替换文本起点；原文末尾固定映射到合并结果末尾）；
  - `mergedToOrig(p)`：合并结果偏移 → 原版本偏移（插入文本内部映射到原区间起点；
    合并结果末尾固定映射到原文末尾）。

注意：删除（空替换文本）区间的左边界与插入文本内部位置没有唯一反向映射，
属于位置映射的固有歧义点，枚举测试中按豁免处理。

## 测试

```sh
npm test   # tsc 编译 + node --test
```

测试内容：

- 6 个规则单测（不相交合并、同点插入按分支 ID、相同编辑去重、重叠冲突取舍、
  删除包含修改冲突、位置映射取值）；
- 短字符串全区间枚举核对：长度 ≤4 的全部字符串（字母表 {a,b}）× 全部
  单编辑区间对（41067 个场景），以及长度 ≤2 × 每分支两个编辑（38016 个场景）。
  每个场景核对：分段可重建合并文本、分段连续性、双向映射单调性与往返一致性、
  以及与独立参考实现（倒序 splice）的结果对比、冲突判定与取舍正确性。
