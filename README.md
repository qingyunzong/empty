# switchsim — 多入口多出口交换机离散事件仿真

纯 Go 标准库实现，不发真实网络流量。时间为整数 tick，每 tick 每端口至多发送一个包。

## 模型

- **拓扑**：N×N 交换机，每入口每 tick 至多发一个包，每出口每 tick 至收受一个包。
- **调度**：每 tick 计算一次输入-输出匹配（轮转优先级贪心最大匹配）。
  争同一出口的入口每 tick 至多一个获准；无竞争的请求必被满足（匹配的最大性），无竞争出口照常推进。
- **队列模式**（可比较）：
  - `ModeFIFO`：每入口单一队列，存在队首阻塞（HOL blocking）；
  - `ModeVOQ`：每入口按出口分虚拟输出队列，消除队首阻塞。
- **离散事件**：包到达是整数 tick 上的事件（`Simulator.AddArrival`），
  每 tick 先注入到达包，再执行匹配调度（`Simulator.Run`）。
- **丢包**：队列容量有限，满则丢弃并计数。
- **守恒**：任意时刻 `注入 = 已收 + 已丢 + 队列中`，包数与字节数均成立（`Switch.CheckConservation`）。

## 运行样例

```sh
go run ./cmd/demo
```

输出（4×4 交换机，2000 tick，每入口到达率 0.7，热点出口概率 0.5，固定随机种子）：

```
模式              注入包      收到包      丢弃包       注入字节       收到字节       丢弃字节     平均时延
FIFO(HOL)      5562     3298     2264    2857216    1689280    1167936   75.42T
VOQ            5562     4166     1396    2857216    2133440     723776   60.04T

守恒校验: 注入 = 收到 + 丢弃 + 队列残留（包数与字节数均通过）
```

相同流量下 VOQ 吞吐更高、丢包更少、时延更低——队首阻塞的代价清晰可见。

## 测试

```sh
go test ./...
```

覆盖：同出口竞争每 tick 至多放行一个、无竞争出口同步推进、VOQ 消除 HOL 阻塞、
队列满丢包计数、随机流量下逐 tick 收发丢守恒、每 tick 每端口至多一包、热点流量下 VOQ 优于 FIFO。

## 文件

- `switch.go` — 交换机、队列、匹配调度、统计与守恒校验
- `sim.go` — 离散事件仿真器（整数 tick 到达事件）
- `cmd/demo/main.go` — FIFO 与 VOQ 对比样例
- `switch_test.go` — 全部测试
