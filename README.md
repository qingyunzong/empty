# serialcheck — 事务调度冲突可串行化判定

读取标准输入中的事务读写操作（至多 12 个事务），构建冲突依赖图：

- **有环**：判定不可串行化，输出环上的具体读写冲突边（含数据项与操作序号）。
  若事务数 ≤ 8，额外枚举全部排列，提示是否存在视图等效串行顺序。
- **无环**：判定可串行化，用 Kahn 算法每轮取当前可执行事务中 ID 最小者，
  输出逐轮拓扑序与等效串行顺序，并独立重放验证所有读操作版本与原调度一致。

## 输入格式

两种记号可混合，`#` 后为注释：

```
r1(A) w1(A) r2(A) w2(B)   # 紧凑式
1 R A  2 W A              # 三元组: 事务号 R|W 数据项
```

版本语义：事务 t 的写产生版本 t，初始版本为 0；读操作读取调度中此前最近写入的版本。

## 运行

```
go run . < input.txt
go test ./...
```

## 实现要点

- `schedule.go`：解析、`BuildEdges`（WR/RW/WW 冲突边）、`FindCycle`（DFS 找环并映射回具体边）、
  `TopoMinID`（每轮最小 ID 的 Kahn 拓扑）、`ReplayEquivalent`（独立重放验证）、
  `EnumerateValidOrders`（小历史排列枚举对照）。
- `schedule_test.go`：单测 + 300 组随机小历史的排列枚举交叉验证
  （无环 ⇒ 枚举存在有效顺序且拓扑序在其中；冲突有环但视图可串行的经典反例单独覆盖）。
