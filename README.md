# 流媒体帧与文本消息交错

流媒体采集把美元字节一律当成新帧时，正文里的同一个字节会把后半段切掉。实现可导入的Go组件，供流媒体采集调用，不建立连接。处于消息边界时，0x24开始一个二进制帧：随后1字节通道、大端uint16长度和正好这么多原始载荷。长度大于宿主maxFrame时在这2字节可读后拒绝，不按声明分配。其他字节开始一条文本消息，以CRLF分行，空行结束头部。头是名字、冒号、可选一个空格和值。名字不区分大小写，返回时用小写。content-length至多一次，值是无前导零的非负十进制。有它时，空行之后正好是这么多原始字节，这些字节里的0x24仍属于正文。没有它时正文为空。文本消息的起始行和头必须是严格UTF-8，正文按原始字节保留。单独的CR失败。Push可停在二进制帧或正文中间；Finish时消息未完成则失败。失败停止组件，已交付消息保留。测试独立组流，覆盖正文中的0x24、消息边界上的0x24、重复content-length和帧被切开。期望消息不得调用被测组件生成。
