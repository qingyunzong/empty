# transportplan

固定分配运输规划库（仅 Go 标准库）。一个不可拆分的订单→线路分配必须
**同时**满足两种公开容量场景，目标为最小化两场景费用的较大者（minimax）。

## 模型

- 至多 8 个订单、6 条线路（`MaxOrders` / `MaxLines`），订单不可拆。
- 每条线路：两场景各自的公开容量、启用固定费、服务的温区、两场景各自的到达耗时。
- 共享温区容量：同一温区所有线路上的订单需求合计不得超过 `ZoneCap`。
- 订单时窗：线路到达耗时须落在订单时窗内，且两个场景分别合法。
- 订单前置约束：`Precedence` 中的 (i, j) 要求 i 的到达不晚于 j（两场景均须成立）。
- 场景费用 = 已启用线路固定费 + 订单分配费；目标 = min max(场景0费, 场景1费)。

## 接口

- `Problem.Validate` / `Check` / `Feasible` / `Costs`：约束校验与费用。
- `Certify`：输出双场景逐线路容量证书（各线载荷/容量、到达时间、温区用量、
  两场景费用与违规清单）。
- `Enumerate`：全分配枚举（lines^orders），给出最优解、可行解计数与
  Pareto 前沿，作为小规模问题的真值核对。
- `Solve`：分支定界搜索，保存 Pareto 前沿，并报告最优值与已证明的
  上下界（搜索完备，结束时 Lower == Upper == 最优值）。

## 测试

`go test ./...` 包含：约束单测、双场景证书单测，以及分支定界与全枚举
在 60 个随机小规模实例和 1 个 8 订单 × 6 线路全尺寸实例上的对拍。
