# 寄存器帧的长度与功能布局

寄存器采集把多条帧粘在同一个字节流里，长度若把前6字节也算进去，下一条的功能码就会错位。实现可导入的Go组件，供寄存器采集调用，不连接设备。每帧以7字节头开始：大端uint16事务号、大端uint16协议标识、大端uint16长度、uint8单元号。协议标识必须为0。长度包含单元号及其后的PDU，不含前6字节，合法范围是2至254；一旦这2字节可读且超出范围就拒绝，不按声明分配。PDU第一字节是功能码。正常功能只接受3、4、6、16和23。功能3和4的请求是两个大端uint16，起始地址和数量，数量为1至125。二者的正常响应是uint8字节数加正好这么多数据，字节数必须为2至250的偶数。功能6的请求和响应相同，都是大端uint16地址和uint16值。功能16的请求是大端uint16地址、uint16数量、uint8字节数和数据；数量为1至123，字节数必须等于数量的两倍。功能16的响应只有地址和数量。功能23的请求依次是读地址、读数量、写地址、写数量、字节数和写数据；读数量1至125，写数量1至121，字节数等于写数量的两倍。功能23的响应与功能3的响应布局相同。功能码等于上述值加128时是异常，后面只能有一个1至4的异常码。长度必须正好等于实际PDU加1，不能多字节也不能在字段中间结束。事务号和单元号原样返回，不在组件内配对请求。Push可停在头或数据中间；Finish时仍有残余则失败。失败停止组件，已交付帧保留。测试独立组帧，覆盖长度含前6字节、数量0、功能16字节数不符、异常码5、功能23的两段数量、响应字节数为奇数，以及头被切到下一块。期望帧不得调用被测组件生成。
