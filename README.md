# testplan — 精确测试选择规划器

从至多 **24 个候选测试**中选择一个子集，覆盖全部**公开分支**与**成对交互**
（特性取值的两两组合），满足测试间的**启动前置**（requires 闭包）与**总时限**约束。
目标为字典序最优：**先总成本最小，再测试数量最少**。

仅使用 Go 标准库，无第三方依赖。

## 用法

```sh
go build -o testplan .
./testplan solve  -f examples/demo.json [-cert cert.json]  # 求解并输出摘要/覆盖证书
./testplan check  -f examples/demo.json                    # 与穷举搜索交叉核对
./testplan example                                         # 打印示例实例
```

## 实例格式（JSON）

- `branches`：需覆盖的公开分支列表。
- `features`：特性及其取值；全集自动包含所有两两取值组合（成对交互）。
- `time_limit`：所选测试 duration 之和的上限。
- `tests[]`：`name`、`cost`、`duration`、`requires`（前置测试，可成环，
  按传递闭包处理）、`branches`（覆盖的分支）、`assign`（特性赋值；
  一个测试覆盖其所有赋值特性两两组合成交互对）。

## 求解与最优性证明

- 贪心构造初始上界；深度优先分支限界搜索精确最优解。
- 下界：对每个未覆盖元素取覆盖它的最小测试成本，求和后除以单测试最大
  覆盖数（`costLowerBound`），并配合后缀最大覆盖数给出测试数下界。
- 剪枝：后缀覆盖并集不可达、成本下界不优、时限超限。
- 输出**覆盖证书**（JSON）：所选测试、覆盖元素清单、用时、
  `bounds.lower/upper/optimal`、搜索统计与 FNV-1a 校验和。
- `check` 命令对全部 2^n 个子集穷举，验证分支限界结果一致（小实例核对）。

## 实测结果

`go test ./...`（go1.27.1 linux/amd64，2026-10-05）：

```
ok  	testplan	0.025s
```

- 随机小实例（n≤14，300 个种子）分支限界与穷举逐一比对一致。
- 24 测试压力实例 3 个：求解 5–23ms，并与 2^24 全量穷举核对一致。
- 示例实例 `examples/demo.json`：最优 cost=39、7 个测试、用时 100/100，
  下界 24 → 收敛至 39，搜索 487 节点（穷举需 4096）。
