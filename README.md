# 同步对象库（sync-object-store）

TypeScript + Node.js 内置库实现的多副本同步对象库，无第三方依赖。

## 核心语义

- **墓碑删除**：`remove()` 只写墓碑（`deleted: true`、数据清空），不物理移除记录；
  即使对象本地未知也写墓碑，防止迟到的旧 `put` 乱序到达时复活对象。
- **阻塞引用**：活文档引用墓碑对象（或缺失对象）时，`blockedReferences()` 报阻塞，
  列出 `{document, object, reason}`；重新 `put` 覆盖墓碑后阻塞解除。
- **垃圾回收**：墓碑仅当同时满足两个条件才回收——
  1. **全副本确认**：所有已知副本的版本向量均覆盖产生该墓碑的删除操作；
  2. **无任何根引用**：无活文档引用，也无历史快照（根）引用。
- **乱序合并**：操作携带混合逻辑时钟（HLC：时间戳 + 副本 ID 决胜），
  按最后写入者胜出合并；按 `(replica, seq)` 去重，乱序/重复投递幂等，多副本收敛。
- **快照释放验收**：历史快照作为 GC 根固定可达对象；释放快照后——
  - 不复活对象：已回收对象靠去重集抵御旧操作重投，删除状态不被回滚；
  - 不删仍可达墓碑：仍被活文档或其他快照引用的墓碑保留，并继续报阻塞。

## 结构

- `src/hlc.ts` — 混合逻辑时钟比较
- `src/vector.ts` — 版本向量（覆盖/合并）
- `src/store.ts` — `Replica`：记录、墓碑、文档、快照、合并、阻塞检测、GC
- `src/sync.ts` — `SyncNetwork`：副本间日志投递（可种子化乱序）与确认交换
- `test/` — `node:test` 测试

## 运行

```sh
npm test    # tsc 编译到 dist/ 后运行 node --test
```

## 实际测试结果

环境：Node.js v22.22.1，TypeScript 7.0.2（全局 tsc），2026-10-05 执行。

```
$ npm test
ok 1 - dist/test/gc.test.js
ok 2 - dist/test/store.test.js
ok 3 - dist/test/sync.test.js
# tests 3
# pass 3
# fail 0
```

逐用例结果（共 11 个，全部通过）：

```
ok - GC 需全副本确认：任一副本未确认则墓碑保留
ok - GC 需无历史根引用：快照引用阻止回收，释放后才可回收
ok - 快照释放验收：不复活对象、不删仍可达墓碑
ok - GC 后重投旧操作不复活对象（去重保护）
ok - 删除对象留下墓碑，数据清空但记录保留
ok - 删除本地未知对象也写墓碑，迟到的旧 put 不复活对象
ok - 活文档引用墓碑对象报阻塞，重新 put 后解除
ok - 引用缺失对象同样报阻塞（reason=missing）
ok - 合并乱序且幂等：重复投递不改变状态
ok - 乱序合并收敛：多副本随机乱序投递后状态一致
ok - 并发写同对象按 HLC 决胜，全副本结果一致
```
