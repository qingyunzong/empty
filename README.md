# merklefs

清单库：遍历虚拟目录（`fs.FS`）生成确定性清单，计算 Merkle 根并为任意文件生成包含证明。仅使用 Go 标准库。

## 设计

- **遍历**（`walk.go`）：`Walk(fsys, root)` 基于 `fs.WalkDir`，符号链接只记录目标、绝不跟随（`fs.ReadLinkFS`，MapFS 回退 `ReadFile`）；硬链接经 `(dev, ino)` 识别为同一对象，共享 `ObjID` 且内容只哈希一次；无 inode 信息的虚拟文件系统按路径区分对象。
- **路径规范编码**（`canonical.go`）：相对、斜杠分隔、干净路径；`utf8.ValidString` 拒绝非规范 UTF-8（过长编码、代理项、越界码点）；条目按 UTF-8 字节序（即码点序）排序。
- **Merkle 树**（`merkle.go`）：RFC 6962 风格域分离，叶 = `SHA-256(0x00 || 规范记录)`，内部节点 = `SHA-256(0x01 || 左 || 右)`；奇数节点直接晋升上一层。`Prove`/`ProvePath` 生成证明。
- **独立验证器**（`verify.go`）：`VerifyProof` 只依赖公开规范（记录编码与域分离常量），自行从条目重算叶哈希、由 `Index`/`Size` 推导每层应有的兄弟位置（含奇数晋升），逐步重放并与根比对；拒绝步数不符、方向错误、元数据不一致的证明。
- **增量更新**（`update.go`）：`Manifest.Apply(changes...)` 按 Upsert/Remove 变更有序条目集合并重算根，无需重新遍历文件系统；`ObjID = SHA-256(dev‖ino)[:16]` 使增量与全量重建结果一致。

## 测试结果

`go test ./... -count=1`（go1.27.1 linux/amd64，2026-10-05 实际运行）：

```
ok  	merklefs	0.005s
```

17 个测试全部 PASS，覆盖：MapFS/真实目录遍历、符号链接不跟随、硬链接同对象、UTF-8 字节序排序、非规范 UTF-8 拒绝、根确定性与序无关、全条目证明验证、**逐层损坏**（每层兄弟哈希翻转、方向翻转、叶/路径/根/索引损坏、截断/加长证明均拒绝）、增量变更与全树重建根一致、空清单往返。
