# scanalign

校正工具输入物品的预期顺序与实际扫码序列：允许重复条码、漏扫和错序，
求最少的删除/插入操作，并在平局时输出字典序最小的编辑脚本。
相同条码按位置保留——每个出现都是独立槽位，不做去重。

## 用法

```sh
go run ./cmd/scanalign [-edits-only] <expected-file> <scanned-file>
```

每个文件每行一个条码，`-` 表示从标准输入读取（只能有一个输入用 `-`）。
标准输出为可重放脚本，每行一个操作：

- `keep <条码>`：预期物品被扫到，原样通过
- `del <条码>`：预期物品漏扫，从序列中删除
- `ins <条码>`：多扫/错扫的物品，插入序列

`-edits-only` 只输出 `del`/`ins` 行。标准错误输出距离摘要，
例如 `distance: 2 (del: 1, ins: 1)`。

## 重放

`align.Replay(expected, ops)` 按脚本消费预期序列并重建扫码序列；
`align.Format` / `align.Parse` 负责脚本的序列化与解析。

## 平局规则

所有最优脚本长度相同（keep/del/ins 数量各自固定）。平局时按操作
token 逐条比较取字典序最小者，即 `del ...` < `ins ...` < `keep ...`，
同种操作按条码字符串比较。

## 算法

后缀 DP：`dp[i][j]` 保存 `expected[i:]` 与 `scanned[j:]` 的
（最小编辑代价, 字典序最小编辑脚本），脚本用不可变链表共享后缀，
时间复杂度 O(m·n·L)（L 为脚本比较长度），空间 O(m·n)。

## 测试

```sh
go test ./...
```

测试包含短串全编辑路径枚举的参考核验：对字母表 {a,b}（长度 ≤ 5）和
{a,b,c}（长度 ≤ 4）的所有序列对，逐一比对 `Diff` 输出与暴力枚举的
最小代价及字典序最小脚本，并验证重放结果等于扫码序列。
