递归解析器需要可导入的 Go DNSSEC 验证包，调用方提供已解析且保留原始规范名的 DNSKEY、DS、RRSIG、NSEC、NSEC3 与查询上下文，不由组件发网络请求。验证链必须从指定信任锚逐区到目标 RRset，区分 secure、insecure、bogus、indeterminate；算法或摘要不支持只能在确有受信委派时产生 indeterminate，不能当作签名成功。实现 RFC 4034/4035 的规范名称排序、通配符合成与原始 owner 校验，并按 RFC 5155 验证 NSEC3 opt-out、closest encloser、next closer 和 wildcard 不存在证明；攻击者可控制全部非锚记录，混入跨区记录、过期签名、错误 key tag、NSEC 环空洞或高迭代 NSEC3 时必须拒绝且不污染已缓存的受信 RRset。时钟、允许算法、最大哈希迭代和缓存由调用方注入，缓存键绑定区、RRset、验证时刻区间及信任锚世代。用独立签名夹具和小型名称空间枚举核对正常存在、NXDOMAIN、NODATA、通配符、无签委派与 opt-out，明确区分有效否定证明和看似覆盖但缺少 next-closer 证明的伪造应答。
