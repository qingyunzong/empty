# 导入数据的循环外键装载计划

离线数据恢复时，表间外键可能形成环。Go装载规划包供恢复宿主调用，输入表ID、行主键及可空外键，先校验所有非null引用存在且主键唯一；对有环依赖只能先把允许延迟的外键置null装载，再补写。每条外键指向一条行，依赖按行而非表建立；至多20条候选延迟边，求置null字段数最少的方案，并列按表/行/字段ID列表字节序，不能只删任意反馈边。返回装载拓扑顺序（就绪行按表ID再行ID字节序）及补写操作，非可空边不得延迟。以小图全子集核验可恢复性。

## 包入口

`BuildPlan(rows []RowRef, refs []Reference) (*Plan, error)`

- `RowRef`：表 ID + 行主键，唯一定位一条行。
- `Reference`：源行、字段 ID、目标行指针（`nil` 表示空值外键）与 `Nullable` 标志；
  非 null 外键形成“源行依赖目标行”的行级有向边，空值外键不形成边。
- `Plan.LoadOrder`：全部行的装载顺序，就绪行按表 ID、再按行 ID 的字节序出队。
- `Plan.DeferredFields`：被临时置 null 的外键，按表/行/字段 ID 字节序排列。
- `Plan.Backfills`：行装载后执行的补写操作，与延迟字段一一对应、同样按字节序排列。

## 算法

1. 校验主键唯一、外键单元格不重复、所有非 null 引用目标存在；非可空外键不允许空目标。
2. 非可空边为固定边。若固定边子图自身成环，返回包装 `ErrNonDeferrableCycle` 的错误，
   数据集不可恢复。
3. 可空边是候选延迟边（上限 `MaxDeferrableEdges = 20`）。以候选边为顶点构造依赖图：
   候选边 `i` 的目标沿固定边可达候选边 `j` 的源时连弧 `i -> j`。原行级图的环与该
   依赖图的环一一对应，问题归约为不超过 20 个顶点的最小反馈顶点集。
4. 按延迟边基数递增枚举子集（同基数按下标字典序，配合候选边的字节序排列），
   第一个使依赖图无环的子集即为“置 null 字段最少、并列时字节序列最小”的方案，
   而非任意删除一条反馈边。
5. 去掉延迟边后在行级 DAG 上做 Kahn 拓扑排序，最小堆保证就绪行的字节序确定性。

## 错误哨兵

- `ErrInvalidRequest`：空 ID、重复主键、重复外键单元格、非可空边空目标等。
- `ErrUnresolvedReference`：非 null 外键指向输入中不存在的行。
- `ErrNonDeferrableCycle`：仅由非可空外键构成的环，无法延迟。
- `ErrTooManyDeferrableEdges`：候选延迟边超过 20 条。

错误均被 `PlanError` 包装并携带定位上下文，可用 `errors.Is` 判定类别。

## 验证

- `go test ./...` 运行全部测试。
- `TestExhaustiveSmallGraphs` 对 1..3 个顶点的全部“边存在性 × 边类型”组合做全子集
  核验，用独立 DFS 预言机交叉验证最小延迟集合、字节序裁决、拓扑顺序与可恢复性。
- `TestRandomLargerGraphs` 在 4..6 个顶点上做 2000 组随机抽样，覆盖固定/可空平行边、
  行级自环与多表字节序场景。
