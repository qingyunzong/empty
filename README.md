# 紧凑列表的反向长度核验与局部拼接

归档接入宿主要直接检查并编辑紧凑列表页，不能相信页头元素数或把反向长度当作前一项长度。交付Go可导入的页库，使用下列封闭LP1编码，不承诺兼容任一Redis版本。头为总字节数u32小端、元素数u16小端，尾恰一个0xff；总长包括头尾且必须等于输入长度。元素数65535表示未知，其他数必须与扫描一致。每元素由正文加反向长度组成。正文首字节b<128时是整数b；b在0x80..0xbf时是长度b&63的原始字节串；0xc0..0xdf时与下个字节拼13位二补码整数；0xe0..0xef时长度=((b&15)<<8)|下字节，随后该长度字节串；0xf0后u32小端长度及字节串；0xf1/0xf2/0xf3/0xf4后分别16/24/32/64位小端二补码整数，其他前缀非法，0xff只能在页尾作为终止。读取接受较宽整数和字符串编码，但不把数字字节串自动变为整数，二者是不同值类型。令L为正文全部字节数、不含反向长度；将L用最少数量的7位组大端写出，第一组高位为0、其余各组高位为1，例如L=128是01 80，L=500是03 f4；最多5组，L不能0，禁止冗长前导零组。反向从元素末字节向左读取，遇高位0结束，必须确认解出的L恰好落到正文起点，且该正文前向解出的长度与L相符；不能把反向字段自身宽度加进L再编码。Open先完整核验页并返回不可变快照；不得保留每个元素的起点表或全部解码值，额外长期元数据只允许头计数及常数个游标。提供头向前和尾向后的游标，Prev必须从当前边界前的反向长度定位，不准重新从页头扫描来伪装反向访问；每步返回正文类型和值、物理范围，所有游标只属于其原快照。宿主通过Splice(startIndex,deleteCount,newValues,byteBudget)建立新快照，索引按旧页元素序且允许末尾插入，范围越界拒绝；整数新值使用可表示它的最短正文编码，字符串使用最短长度前缀，反向长度采用上述最短组。原页中未删除元素的整个编码逐字节保留，即使其正文不是最短，也不能顺便重编码；可复制页字节，但不能先全解码再全编码。新页头计数小于65535写精确值，否则写65535，总长度先用宽整数计算，超uint32或byteBudget时返回容量不足而旧快照及全部旧游标仍有效。Open失败不交付游标，Splice失败不交付半页；返回的新字节不得与调用方可变输入或旧快照共享可写区域。提供真实接入页编辑调用例、独立全解码列表模型及独立编码夹具，随机交替插入删除后核对值序列、正反游标逆序、头计数和未触碰元素的原始编码；覆盖空页、连续整数端点-4096/4095、24位负数、int64最小值、63/64与4095/4096字节字符串、正文127/128/16383/16384长度边界、页头未知计数实际很少、正文中合法0xff、尾部额外字节、反向长度可落在载荷内部的伪造页和差1预算。添加可观测字节读取计数，验证通过Open后的尾部Prev只读该元素正文及至多5字节反向字段，不全页重扫。

## 交付物

可导入的 Go 页库位于 `lp1/`（导入路径 `example.org/dataeng/q0317/lp1`），根包保持为空占位。

- `lp1.Open(page)` 完整核验后返回不可变 `*Snapshot`，输入字节被复制；失败只返回 `ErrMalformed`，不产生游标。
- `Snapshot.Head/Tail` 产出常数大小游标；`Next` 前向解析正文，`Prev` 仅从边界前的反向长度向左定位，绝不从页头重扫。
- `Snapshot.ByteReads/ResetByteReads` 暴露 Open 之后游标实际读取的页字节数；Open 自身的核验不计入。
- `Snapshot.Splice(start, delete, values, budget)` 以原始字节复制保留未删除元素，仅对新值做最短编码；超 uint32 或 `budget`（0 表示不限）返回 `ErrCapacity`，旧快照与旧游标继续可用。
- 反向长度在 Open 中通过枚举 1..5 组宽度并交叉验证“前向最小字段 == 反向解出 L == 正文起点”来核验，因此反向字段落在载荷内部、前导零冗余或超 5 组的伪造页都会被拒绝。

测试均在外部包 `lp1_test` 中，`fixtures_test.go` 是独立重写的编码/全解码夹具，`random_test.go` 做随机交替插入删除，`example_test.go` 是真实接入编辑的可运行示例，`fuzz_test.go` 覆盖任意字节输入与随机 Splice。运行：

```
go test ./...
go test ./lp1/ -fuzz FuzzOpenNoPanic -fuzztime 30s
```
