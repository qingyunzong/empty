# batchsched — 租户轮询批处理调度库

仅使用 Go 标准库。核心包为 `sched`（`batchsched/sched`）。

## 调度模型（赤字轮询 DRR）

- **按租户轮询**：租户组成环形队列，游标轮转，每次调度队首任务后游标后移。
- **每轮整数额度**：每轮给每个有待办任务的租户赤字计数器增加固定整数额度 `quantum`。
- **大任务跨轮积累**：队首任务费用超过当前赤字时等待，赤字逐轮累积直到足以支付；
  队列清空时赤字归零（不囤积额度）。
- **紧急任务每轮最多两件**：紧急任务进入全局 FIFO，绕过赤字，但每轮最多注入
  `urgentCap` 件（经典取值为 2），且不消耗租户额度。
- **取消不留虚扣费**：取消排队中的任务零费用、完全不触碰账户；取消运行中的任务
  按未消耗比例退费（`refund = cost * 剩余轮数 / 总时长`，向下取整），账户只保留
  已消耗部分。

## 虚拟时钟重放 vs 逐轮朴素模型

- `ReplayScheduler`：事件驱动。虚拟时钟直接跳到下一个可能改变状态的轮次
  （外部事件、任务完成、或某租户赤字累积到队首费用的那一轮），跳过轮次的整数
  额度一次性补记。跳轮之所以正确，是因为两次关键轮次之间队列不变、没有任务
  变得可支付、活跃租户集合恒定，额度累积是线性的。
- `NaiveScheduler`：参考模型，逐轮显式推进同一策略核心。
- `TestReplayMatchesNaive`：300 个随机种子的负载下核对两者调度记录与账单完全
  一致，并校验无饥饿（每个未取消任务都完成）、费用准确（账实相符、取消排队
  任务零费用、取消运行任务只计已消耗部分）。

## 运行测试

```sh
go test ./...
```

```
ok  	batchsched/sched	0.069s   # go test ./... -count=1
ok  	batchsched/sched	1.389s   # go test ./... -count=1 -race
```

8 个测试全部通过，其中属性测试含 300 个随机种子子用例（全部 PASS）。
