# dep-test-executor

Dependency-graph test executor in TypeScript using only Node.js built-in
modules (no runtime or dev dependencies; the globally installed `tsc` is used
to compile).

## Semantics

- **Cycle isolation**: strongly connected components (Tarjan, iterative) with
  a cycle (size > 1 or self-loop) are isolated together with *all* transitive
  dependents. Everything else stays executable.
- **Failure cancellation**: a failing case cancels its transitive dependents
  only. Siblings (cases sharing a prerequisite with the failed case) still run.
- **Stable output**: `results()` and `formatResults()` are always sorted by
  case id, independent of definition or execution order.
- **Start-set cross-check**: `crossCheckStartSet()` compares the start set of
  the controllable executor (incremental remaining-dependency counters) with
  the full-graph classification model (batch `planFullGraph`) and throws on
  any mismatch.

## Layout

- `src/graph.ts` — graph building, Tarjan SCC, cycle/downstream classification
- `src/executor.ts` — `ControllableExecutor` (`readySet()`, `step()`, `runAll()`, `results()`)
- `src/model.ts` — full-graph batch classification (`planFullGraph`)
- `src/crosscheck.ts` — executor vs. model start-set agreement check
- `test/` — `node:test` suites; `record-results.test.ts` also writes
  `results/actual-results.json` on every run

## Commands

```sh
npm test    # tsc build + node --test
npm run build
```

## Actual results

`npm test` (Node v22.22.1, tsc 7.0.2): **5/5 test files pass, 0 fail**.

`results/actual-results.json` (regenerated by `npm test`) for the
representative fixture — `db` fails, `cycle-a`/`cycle-b` form a cycle:

- start set (executor = model): `boot`, `config`, `lint`
- isolated (cycle SCC + downstream): `cycle-a`, `cycle-b`, `report`
- cancelled (failure downstream): `api`, `ui`
- passed: `boot`, `config`, `lint`; failed: `db`
