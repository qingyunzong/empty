# 数据块读取的区间合并计划

可导入的 Go 规划包（`example.org/dataeng/q0166`，包名 `dataeng`），为按范围计费的远程列存储扫描宿主计算最低费用的读取请求集合。

## 费用模型

- 每次请求费用 = 非负有理固定开销 `Fixed` + 非负有理每字节费用 `PerByte` × 请求跨度（用 `math/big.Rat` 精确计算）。
- 请求跨度不得超过正整数 `MaxSpan`（M）。
- 允许为合并请求额外读取需求之间的间隙。

## 用法

```go
res, err := dataeng.Plan(
    []dataeng.Interval{{Start: 0, End: 5}, {Start: 9, End: 10}},
    dataeng.Params{
        FileLen: 10,
        MaxSpan: 10,
        Fixed:   big.NewRat(100, 1),
        PerByte: big.NewRat(1, 1),
    },
)
// res.Requests = [{0 10}]，res.Cost = 110，res.Covers = [[0 1]]
```

- 输入：文件长度与所需非空半开字节区间 `[Start, End)`；先排序归并重叠（含相邻）区间，结果见 `Result.Merged`。
- 输出：`Result.Requests` 为最优请求列表，`Result.Covers[k]` 为第 k 个请求覆盖的原始需求下标（升序），`Result.Cost` 为总费用。
- 并列规则：费用最低者优先；其次请求数更少；再其次请求范围列表字典序最小（区间按 Start 再 End 比较）。
- 不可行：若某归并后区间长度超过 M，返回 `Feasible=false`、`Requests=nil`，并在 `Result.TooLong` 中列出全部超长需求区间。

## 规范性证明（为何只需考虑切分）

设归并后的区间为 I_1..I_n（互不相交、有序）。任取一个可行请求集合：

1. 将每个归并区间指定给恰好一个覆盖它的请求，并把每个请求收缩到其负责区间的 [最小起点, 最大终点)。每字节费用非负 ⇒ 收缩不增费用；收缩后的跨度含于原请求 ⇒ 仍不超过 M。
2. 收缩后没有负责区间的请求可丢弃，固定开销非负 ⇒ 不增费用。
3. 若请求 A 负责 I_i、I_k 而请求 B 负责 I_j（i<j<k），把 I_j 改派给 A：A 本已跨过它，费用不变，B 变空后可删。重复此过程，请求变为互不相交、按序排列，且每个请求恰好是某段连续归并区间组的 [首区间起点, 末区间终点)。

因此重叠请求无益，把请求起止限制在归并区间边界（自然也不跨文件端点）不损失最优性；最优解必可在「把 I_1..I_n 切分为连续组」的方案中找到。包内用 O(n²) 动态规划枚举所有切分（`dp[j] = min over i<j, 跨度≤M of dp[i] + 组费用`），按（费用, 请求数, 字典序）三元序比较，故输出即最优。字典序比较对完整列表进行，且等费用等请求数时保留字典序最小前缀不会漏解（相同长度下首个差异必在前缀内）。

## 验证

`go test ./...` 包含：

- 归并、间隙合并/拆分、跨度限制、并列规则、有理数费用、不可行与非法输入的单元测试；
- `TestExhaustivePartitions`：小规模随机实例上穷举全部 2^(n-1) 种连续切分，与 DP 结果逐一比对费用与请求列表，并校验请求有序不相交、边界取自归并区间、不跨文件端点、跨度不超限、需求被恰好覆盖一次、费用与模型重算一致。
