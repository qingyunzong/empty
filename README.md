# 采购优化 CLI

按供应商整数量采购：阶梯**全量**单价、运费门槛、起订量（MOQ），最多 6 个供应商，
数量恰等总需求，金额全程使用整数分计算。优化目标：**总费用最小；费用相同时供应商数量最少**。

- 纯 TypeScript + Node.js 内置库（`node:fs` / `node:test` / `node:assert`），零 npm 运行时依赖
- 求解器：按供应商的动态规划，状态为（累计费用，供应商家数）字典序最优，复杂度 O(供应商数 × 需求²)
- 验收：内置全枚举求解器 `solveBruteForce`，在小需求下与 DP 逐一比对

## 计价规则

- 整数量：每个供应商的采购数量为非负整数，所有供应商数量之和恰等于需求
- 阶梯全量单价：按该供应商的采购总量所在档位，**全部数量**按该档单价计价
- 运费门槛：该供应商货款（数量 × 单价）达到门槛则免运费，否则收固定运费
- 起订量：某供应商一旦下单，数量必须 ≥ MOQ，否则该供应商不可选

## 使用

```bash
npm test          # 编译 + 运行全部测试
npm start         # 编译 + 用 config.sample.json（6 供应商 / 需求 200）求解
node dist/src/cli.js 配置.json [--demand N] [--brute]
```

- `--demand N`：覆盖配置中的需求
- `--brute`：同时跑全枚举并交叉校验（仅适合小需求）

配置格式见 `config.sample.json`：`demand` + `suppliers[]`，每个供应商含
`name`、`moq`、`freightThresholdCents`、`freightFeeCents`、`tiers[]`（按 `minQty` 升序）。

## 目录结构

- `src/solver.ts`：计价、DP 求解器、全枚举求解器
- `src/cli.ts`：命令行入口（配置校验、结果输出、枚举校验）
- `tests/solver.test.ts`：单元测试 + 小需求全枚举验收 + 随机 fuzz
- `config.sample.json`：6 供应商、需求 200 的样例
- `types/node-shim.d.ts`：最小 Node 类型声明（环境无 `@types/node`）
