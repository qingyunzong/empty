# scenariomin

场景最小化 CLI：每个事件声明读/写资源，删除事件后重新检查前置条件，
求仍保留失败的最少事件子序列（事件数至多 20）。仅使用 Go 标准库。

## 语义

- 场景是事件的有序列表；每个事件声明 `reads` 与 `writes` 资源集合。
- **子序列**：保持原顺序的事件子集（删除其余事件）。
- **前置检查（合法性）**：子序列中每次读取的资源，必须已被该子序列内
  更早的保留事件写过；否则该子序列为**非法子序列**，非法子序列不算失败。
- **失败判定（预言机）**：场景声明 `fail` 映射（资源 → 坏写者事件 id
  列表）。子序列合法、包含 victim 事件（`victim` 字段，缺省为最后一个
  事件），且 victim 读到某资源的"最后写者"属于该资源的坏写者列表时，
  该子序列失败。
- 输入场景须满足：事件数 ≤ 20、id 唯一、`fail` 非空且引用的写者存在、
  完整序列合法且失败，否则报错。

## 用法

```sh
go run . examples/small.json        # 最小化并输出检测证据
go run . -dump examples/small.json  # 追加枚举所有子序列的逐条判定
go test ./...                       # 运行全部测试
```

退出码：0 = 找到最小失败子序列；1 = 未找到；2 = 输入非法。

## 检测证据输出

1. 完整序列的合法性与失败判定；
2. 按规模统计的子序列检查表（total/legal/failing），标出最小失败规模；
3. 最小失败子序列及其合法性轨迹（每次读观察到谁的写）；
4. 失败证据：victim 各资源"目击者写者 vs 原序列写者"的对比；
5. 最小性证明：所有更小的合法子序列全部通过（穷举计数）；
6. `-dump` 时枚举所有 2^n 个子序列的逐条判定（小例核对最小性用）。
