# 名称冲突且摘要不同则两份都不要

归档里的成员要逐个决定收不收。文件采集用可导入的归档库验收：成员有名称、声明字节数、实际字节数和摘要。名称包含“..”或以“/”开头就跳过该成员，其他成员继续。同一名称出现两次，摘要相同只留第一份，摘要不同则两份都不要。实际字节数和声明不一致，或摘要和调用方期望不一致，该成员失败且不保留已读字节。声明字节数超过调用方上限则不读正文并跳过。归档在最后成员结束前截断时，已通过的成员保留，并标明归档不完整。

## 实现

包 `dataeng`（`Collect`、`Writer`）按自定义二进制归档格式逐个验收成员。

### 归档格式

- 固定标识头 `ARCV1\n`；
- 每条成员记录：`uint32` 大端名称长度、名称字节、`uint64` 大端声明字节数、
  32 字节 SHA-256 摘要、成员正文；
- 名称长度为 0 的 4 字节记录作为结束标记；成员头或正文在结束标记前缺失即为截断。

### 采集规则（`Collect(r, maxMemberBytes, expected)`）

- 名称包含 `..` 或以 `/` 开头：跳过该成员并继续处理后续成员；
- 声明字节数超过 `maxMemberBytes`（`<= 0` 表示不限）：不读正文、直接跳过；
- 实际字节数与声明不一致：成员失败，记录声明/实际字节数且不保留已读字节；
- 归档记录摘要与正文实际 SHA-256 不一致，或与 `expected` 中调用方期望不一致：
  成员失败且不保留正文；
- 同名成员：摘要相同只留第一份；摘要不同则两份都不保留，后续同名成员同样拒收；
- 归档截断：返回的 `Result.Incomplete` 为 `true`，error 包装 `ErrIncomplete`，
  截断前已通过的成员仍然保留；归档帧损坏返回包装 `ErrBadArchive` 的错误。

`Result` 分别通过 `Members`、`Rejected`、`Skipped` 给出收录、失败和跳过的成员，
跳过与失败成员的 `Data` 始终为 `nil`。`NewWriter` 可构造归档，
`WriteMemberWithDigest` 可构造异常归档用于测试。
