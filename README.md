# miniopt — single-node offline query engine + cost-based optimizer

Node.js 22, standard library only. Tests use `node:test`.

## Layout

- `src/catalog.js` — table stats (row counts, per-column selectivity/distinct, indexes), page math
- `src/query.js` — JSON query validation (unknown columns, nested aggregates, join scopes)
- `src/optimizer.js` — plan enumeration, cost model, plan-string rendering
- `src/executor.js` — plan interpreter over `data/<table>.json`
- `src/engine.js` — `explain` / `execute` / `updateStats`, plan cache + invalidation
- `src/cli.js` — CLI entry (`explain`, `execute`, `update-stats`)
- `examples/` — demo database and the three acceptance-scenario queries
- `result.txt` — real CLI output of the three acceptance scenarios

## Database directory

```
db/
  catalog.json   {"tables": {name: {rowCount, columns: {col: {selectivity, distinct}}, indexes: [col]}}}
  data/<t>.json  array of row objects
  plans.json     plan cache (created on first explain/execute)
```

One page holds 100 rows. Scan cost = pages. Index scan (equality predicate on an
indexed column, unclustered) = 1 index page + one page fetch per estimated matching row.

## Query JSON

```json
{
  "from": "users",
  "joins": [
    {"type": "inner", "table": "orders", "on": {"left": "users.id", "right": "orders.user_id"}},
    {"type": "left",  "table": "profiles", "on": {"left": "users.id", "right": "profiles.user_id"}}
  ],
  "where": [{"col": "users.age", "op": ">", "value": 30}],
  "groupBy": {"keys": ["users.id"], "aggregates": [{"fn": "count", "col": "*", "as": "c"}]}
}
```

Operators: `=`, `!=`, `<`, `<=`, `>`, `>=`. Aggregates: `count`, `sum`, `avg`, `min`, `max`.

Semantics:

- Join conditions match non-null values only (null never joins, not even to null).
- `group by` treats null as its own group (distinct from the string `"null"`).
- Aggregates ignore nulls; `count(*)` counts rows, `count(col)` counts non-null values.
- Unknown columns and nested aggregates (an aggregate over another aggregate) are errors.

## Optimizer

Cost = scanned pages + join intermediate (estimated output) rows.

For queries with up to 5 tables the optimizer enumerates **all** candidate plans and
picks the lowest cost; ties are broken by lexicographic plan-string order:

- all ordered binary join trees (inner joins are freely reorderable);
- a left join is a barrier: its left subtree and right table stay fixed, it is never
  rewritten to an inner join, and predicates on its padded (right-side) columns stay
  above it;
- all predicate pushdown positions (every ancestor node from the lowest covering node
  up to the root);
- index scan vs full scan for equality predicates on indexed columns.

Estimated join rows = `L * R / max(distinct(l), distinct(r))` per condition
(left join: at least the left row count). Filter selectivity comes from catalog
column stats (`=` uses `selectivity`, ranges use 0.25).

## Statistics updates and plan invalidation

`update-stats` deep-merges a stats patch into the catalog, then invalidates **only**
cached plans that reference the updated table. For each invalidated plan it reports
old/new plan, old/new cost, and the result-hash delta (old hash, new hash, changed flag).

## CLI

```
node src/cli.js explain       --db DB --query query.json
node src/cli.js execute       --db DB --query query.json
node src/cli.js update-stats  --db DB --table orders --stats '{"rowCount":5000}'
```

`--query` / `--stats` accept a JSON string, a `.json` path, or `@path`.
Errors are printed as `{"error": "..."}` on stderr with exit code 1.

node --test
