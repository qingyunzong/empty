# replplan — 副本放置规划 CLI

从至多 **20 个机房**中为至多 **8 个分片**选择副本位置：每个分片至少
`k` 个副本，且同一分片的副本必须位于**不同的故障域**；每个机房有容量
上限与访问费用，总费用不得超过预算。在所有可行方案中输出**费用最小**
的放置方案，并附**故障域与容量证书**（含 SHA-256 摘要，可独立校验）。
仅使用 Go 标准库。

## 用法

```sh
go build -o replplan .

replplan solve  -i input.json -o plan.json   # 求解并输出方案+证书
replplan verify -i input.json -p plan.json   # 独立复核证书
replplan brute  -i input.json                # 暴力枚举最优值（小输入对拍）
```

`-i`/`-p` 缺省为 `-`（标准输入），`-o` 缺省为标准输出。
退出码：`0` 成功，`1` 不可行或证书校验失败，`2` 用法/IO 错误。

## 输入格式

```json
{
  "budget": 60,
  "sites":  [{"id": "bj1", "domain": "beijing", "capacity": 2, "cost": 4}],
  "shards": [{"id": "orders", "replicas": 3}]
}
```

- `domain`：故障域标识；同一分片的任意两个副本不得同域。
- `capacity`：该机房最多容纳的副本总数（跨所有分片）。
- `cost`：每放置一个副本的访问费用。

## 求解方法

最小费用流：源点 → 分片（容量 k）→ 每分片每故障域节点（容量 1，
保证同分片副本故障域互异）→ 该域内机房（容量 1，费用为机房访问费）
→ 汇点（容量为机房容量）。所有费用非负，故最优解每分片恰好 k 个
副本。若最小费用仍超过预算则判定不可行。

## 证书

`solve` 输出的 `certificate` 段包含：

- 每个分片：要求/实际副本数、故障域列表、互异性与数量是否满足；
- 每个机房：已用/总容量、是否超限；
- 总费用、预算、是否在预算内；
- `digest`：规范化放置列表的 SHA-256。

`verify` 不信任方案中的任何字段，从放置列表重新计算全部约束、
费用与摘要并比对证书。

## 测试

```sh
go test ./...
```

`solve_test.go` 在 2000 组随机微小输入（2–6 机房、1–3 分片）上将
最小费用流求解器与暴力枚举对拍，并覆盖：手算答案、故障域/容量/
预算三类不可行、20/8 上限、证书篡改检测（8 种篡改均被拒绝）、
CLI 端到端。
