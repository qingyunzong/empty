# imgdiff — 稀疏镜像比较与搬迁工具

比较由数据区间清单描述的稀疏镜像，输出内容差与布局差的最大半开区间，
并生成把旧镜像变为新镜像的搬迁计划。仅使用 Go 标准库。

## 概念

- 镜像 = 大小 + 有序不重叠的区间清单；区间分 `data`（携带字节）与
  `hole`（洞，读取为零），清单间隙视为洞。
- **洞读取为零**：零数据块与洞**内容相等但布局不同**。`diff` 分别输出
  内容差（按字节比较，洞按零计）与布局差（data/hole 分类不同），均为
  合并后的最大半开区间 `[start, end)`。
- 偏移为无符号 64 位；`start+len` 溢出、越界、重叠、乱序、零长区间
  一律拒绝（`Image.Validate`）。
- 区间可标记 `shared`，表示与父快照共享存储：可读，但写入前必须先
  `unshare`，否则破坏父快照。

## CLI

```sh
imgdiff diff  <old.json> <new.json>
imgdiff plan  -block N <old.json> <new.json>
imgdiff exec  [-state f] [-crash-at K] [-resume] <old.json> <new.json> <plan.json>
```

区间清单 JSON：`{"size": N, "extents": [{"start","len","kind","shared","data"}]}`，
`kind` 为 `"data"|"hole"`，`data` 为 base64。

- `diff` 输出 `{"content": [[s,e]...], "layout": [[s,e]...]}`。
- `plan` 输出搬迁计划（要求两镜像等大、大小为块大小整数倍、区间按块对齐）。
- `exec` 独立执行计划并核对最终内容与洞布局、父快照未被破坏；
  `-crash-at K` 在执行 K 步后中断并保存状态，`-resume` 从中断处继续。

## 搬迁计划

计划把旧镜像逐块变为新镜像，操作：`move`（块间复制，源目标可重叠）、
`write`（写入新数据）、`punch`（打洞）、`unshare`（解除父快照共享）、
`stage-save`/`stage-load`（单块暂存）。

- **先保全仍会读取的旧数据**：依赖图按函数图（每块至多一个读者、一个
  写者）拓扑发射；换环时用唯一的暂存块保存将被覆盖的块，环退化为链，
  绝不存在覆盖未保存来源的步骤。
- **暂存至多一块**：每个环独立解开，暂存块释放后才处理下一个环；
  执行器强制校验。
- **任一步中断后可继续**：每步幂等（没有任何步骤修改自己的源），
  只需记录已完成步数的日志即可恢复；`stage-save`/`stage-load`/`unshare`
  对"已完成但日志丢失"与"写了一半"均可自愈。
- **源哈希防呆**：`move`/`stage-save`/`stage-load` 携带期望内容哈希，
  执行器在复制前核对，循环搬迁一旦覆盖未保存来源立即报错。

## 独立核对

`Machine`（exec.go）是独立于规划器的执行器：单独维护父快照存储，
逐步执行并校验源哈希、暂存块唯一、共享块只读，最后逐块比对最终内容
与洞布局（`Verify`）。测试用小字节数组的暴力展开实现（`diff_test.go`
的 `expand`/`mergeDiffs`）作为参照，对随机镜像交叉核对 `diff` 结果；
对随机旧/新镜像生成计划并验证，且在每个步骤边界模拟两种中断
（半步残骸、日志丢失）后恢复，最终结果仍须完全正确。
