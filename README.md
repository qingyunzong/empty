# 纪元封死之后不能再追加

采集日志一次提交多条记录，每条有纪元、序号和载荷摘要，一批只能有一个纪元。混有多个纪元则整批失败，不封死任何纪元。入库衔接调用可导入的追加日志：一批要么全部写入，要么一条都不写。某纪元尚无记录时只接受序号0。其后序号必须比该纪元已写入的最大序号大1，跳号则整批失败且不改变封死状态。序号与最大序号相同且摘要相同，视为重复，不追加。序号相同但摘要不同，该纪元封死，已写入的保留，此后这个纪元的提交全部失败。出现更大纪元且该批从序号0连续写起时，写入成功并封死所有更小纪元。更小纪元的提交直接失败。

## 结构

- `appendlog`：可导入的追加日志，提供 `Log` 接口与 `MemLog`、`FileLog` 两种实现。`Append` 整批原子提交；`FileLog` 采用长度前缀分帧，重开时丢弃不完整的尾部帧，保证崩溃后仍停在批次边界。
- `dataeng`（包名见 `doc.go`）：采集入库状态机，通过 `NewIngester(log)` 接入追加日志，重放历史后用 `Submit(batch)` 提交 `Record{Epoch, Seq, Digest}` 批次。

## 提交结果

- 成功：返回新追加条数；完全重复的批次返回 0 且不写日志。
- 失败原因用哨兵错误表达：`ErrMixedEpoch`、`ErrEmptyBatch`、`ErrInvalidRecord`、`ErrOutOfOrder`、`ErrDigestConflict`、`ErrSealedEpoch`、`ErrStaleEpoch`。
- 除摘要冲突会写入一条 `seal` 封死标记外，任何失败都不追加该批记录；新纪元晋升时，更小纪元的封死标记与新记录在同一次原子追加中落盘。
