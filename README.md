# resub — 断线续传订阅库

一个 Go 订阅客户端库：断线后从最后确认序号重连，回调成功才推进确认，
失败可重复投递但结果 ID 稳定，新代际取消旧连接，并输出连续不跳号的确认账。

## 语义

- **确认账（Ledger）**：只追加的确认记录 `{Seq, ID, Gen}`，最后一项即重连恢复点。
  `Ledger.Verify(start)` 校验确认链连续、无跳号、无重复。
- **回调确认**：事件只有在回调返回 `nil` 后才写入确认账；回调失败则保持未确认，
  下一连接按最后确认序号重投，重投事件携带相同的结果 ID（幂等去重依据）。
- **代际（Generation）**：每次重连开启新代际，旧连接的上下文被取消并被围栏
  （fenced），旧连接上的 `Recv` 返回 `ErrStaleGeneration`。
- **交付与确认之间断线**：确认前检查连接存活与代际有效，断线则放弃本次确认，
  事件在下一连接按原序号、原 ID 重投，确认账不跳号。
- **协议违规**：服务器跳号（收到非 `last+1` 的新序号）视为致命错误，`Run` 返回；
  已确认序号的重复投递被幂等跳过。

## 结构

- `event.go` — `Event`（含稳定结果 ID）与 `Callback`
- `transport.go` — `Transport`/`Conn` 接口与代际、断线错误
- `ledger.go` — 确认账 `Ledger` 与连续性校验
- `subscriber.go` — `Subscriber` 重连循环、代际管理、确认推进
- `scripted.go` — 受控传输 `ScriptedTransport`：固定事件源、按确认水位恢复、
  代际围栏、故障注入（`DropEvery`、`OnDeliver`、`DropCurrent`）

## 测试

```sh
go test ./...
```

覆盖：断线后按最后确认序号 恢复点重连、回调失败重投且 ID 稳定、
交付与确认之间断线不跳号、新代际取消旧连接、重复投递幂等、
服务器跳号致命化、确认账校验器。
