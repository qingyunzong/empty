登录服务需要可导入的 TypeScript WebAuthn assertion 验证组件，调用方传入挑战会话、预期 origin、RP ID、凭据公钥与持久计数器接口。组件解析 clientDataJSON 和 authenticatorData 的原始字节，校验 type、挑战的 base64url 规范解码、origin 精确匹配、rpIdHash、UP/UV 策略、扩展区长度及签名覆盖的 authenticatorData || SHA-256(clientDataJSON)；支持 COSE ES256 与 Ed25519，拒绝高 S ECDSA、非规范 DER、重复 JSON 键和尾随数据。攻击者可重放旧断言、替换 origin/RP、利用零计数器设备或并发提交同一 signCount；只有签名和全部上下文通过后，才以 compare-and-swap 原子推进凭据状态，同一断言至多一个成功，计数回退返回 cloneSuspected 但不得覆盖较新状态，始终为零的凭据按显式策略处理。挑战一次性消费也必须与验证结果协调：格式或签名失败不消耗，成功后重放不能再次通过。用真实生成的密钥和可控并发屏障测试正常认证、跨站挑战替换、计数竞争、克隆信号及格式歧义，区分恶意断言与合法的零计数器认证器。
