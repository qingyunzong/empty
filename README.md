# 选择重传（Selective Repeat）协议仿真

Python 3.11+ 标准库实现，无第三方依赖。

## 参数约束论证：N ≤ 序号空间 / 2

设序号空间 M=8。若允许窗口 N=5：发送方发出帧 0..4，接收方全部按序接收并交付后，
接收窗口滑动到 [5,6,7,0,1]。若这批 ACK 全部丢失，发送方超时重传**旧帧 0**，
而序号 0 恰好落在接收方的新窗口内，会被误当作"下一周期的新帧"接收并**重复交付**——
接收方无法区分重传的旧帧与新帧，协议正确性被破坏。

当 N ≤ M/2（如 N=4）时：接收窗口滑动后为 [4,5,6,7]，重传的旧帧 0..3 全部落在
窗口之外，不存在二义性。因此本实现在构造 `Sender` / `Receiver` / `Simulation`
时强制校验 `2*N ≤ M`，违反即抛 `ValueError`（如 N=5、M=8）。

## 协议语义

- 每帧独立虚拟定时器，超时仅重传该帧；
- 接收方缓存乱序帧并逐个 ACK，按序交付；
- 接收窗口外帧直接丢弃（不回 ACK）；
- 窗口内重复帧重发 ACK，但不重复交付；
- 发送方仅收到窗口下沿 ACK 才滑动窗口（一次滑过所有连续已确认帧）；
- 虚拟时钟 `advance(t)` 按最早到期定时器触发，同刻到期按序号升序触发。

## 使用

```bash
python -m sr run trace.json
```

`trace.json` 示例（仅帧 1 首传丢失）：

```json
{
  "window_size": 4,
  "seq_space": 8,
  "timeout": 10,
  "num_frames": 3,
  "loss": [1]
}
```

输出 JSON，包含交付序列 `delivered`、重传计数 `retransmissions` 与完整事件序列 `events`。
上述示例的输出为 `delivered = [1, 2, 3]`、`retransmissions = 1`。

## 代码结构

- `sr/protocol.py` — 参数校验、虚拟时钟、发送方、接收方
- `sr/simulation.py` — 丢包信道仿真与事件记录
- `sr/cli.py` / `sr/__main__.py` — 命令行入口
- `tests/test_sr.py` — 单元测试（含验收场景 a–d）
