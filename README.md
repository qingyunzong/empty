# stable-admissions

录取库：按双侧偏好列表与机构容量求稳定分配，支持嵌套分类配额、撤回重算、
无阻挡对证书与极小实例穷举核对。TypeScript + Node.js 内置库，零运行时依赖。

## 运行

```bash
npm test        # tsc 编译 + node --test（需全局 tsc，本环境 typescript@7.0.2）
npm run demo    # 端到端演示：求解 → 证书 → 撤回 → 重算
```

## 模型与规则（精确定义）

- **偏好列表**：每侧给出有序的同级别组（`prefers: string[][]`）。同级偏好按
  ID 字典序固定打破平局，得到全序；未列出的对视为**不可接受**，任何可行
  分配都不会包含不可接受对。
- **嵌套分类配额**：每个机构持有一棵（或多棵）配额树，每个节点有 `quota`。
  申请人可同时属于多个类别；申请人属于某类别时，计入该类别及其全部祖先
  节点。录取集合 S 可行 ⟺ `|S| ≤ capacity` 且对每个配额节点
  `|{a∈S : a 计入该节点}| ≤ quota`（层拟阵约束）。
- **明确替换规则**：机构对录取集合的偏好为可加响应偏好——申请人 x 对机构
  的价值为 `weightBase − rank(x)`（`weightBase = 申请人数 + 1`，保证每位可
  接受申请人的价值为正、即优于空位），集合价值为成员价值之和。机构可拒
  **任意**旧集合 R ⊆ S 以纳新生 a，替换成立（阻挡）当且仅当：
  1. 新集合 `S' = (S \ R) ∪ {a}` 满足全部容量与嵌套配额；
  2. 偏好严格改善：`value(S') > value(S)`。
- **阻挡对**：`(a, i)` 阻挡分配 M ⟺ a 与 i 互相可接受，a 相对当前去向更
  偏好 i（未分配者偏好任何可接受机构），且存在满足上述两条的替换集 R。
- **稳定**：分配可行且不存在阻挡对。

## 组件

- `src/market.ts` — 输入校验（≤10 申请人 / ≤6 机构）、平局打破、配额树、可行性。
- `src/algorithm.ts` — 申请人提议的延迟接受算法；机构用按排名贪心在层拟阵上
  选最优可行子集（可替代选择函数）。
- `src/stability.ts` — 阻挡对搜索（枚举全部替换子集）、无阻挡对证书：对每个
  临界对记录检查过的替换集个数与结论。
- `src/enumerate.ts` — 穷举全部可行分配并逐一检验阻挡对，输出全部稳定方案；
  若结果为空且未超预算，即构成"无稳定方案"的穷举证明（在本规则下延迟接受
  算法保证稳定方案必存在，该分支为防御性设计）。
- `src/session.ts` — 会话 API：`solve({enumerate})`、`withdrawApplicant`、
  `withdrawApplication`，撤回后重算。

## 实际测试结果

`npm test`（Node v22.22.1，tsc typescript@7.0.2，2026-10-05 运行）：

```
ok 1 - dist/test/basic.test.js      # 经典 GS、容量、平局打破、不可接受对
ok 2 - dist/test/enumerate.test.js  # 30 个随机小实例穷举核对 + 10x6 上限实例
ok 3 - dist/test/quotas.test.js     # 嵌套配额、多类归属、替换规则四种情形
ok 4 - dist/test/withdraw.test.js   # 撤回申请人 / 撤回单个申请后重算
# tests 4
# pass 4
# fail 0
```

要点：30 个随机实例（3–5 申请人、2–3 机构、随机嵌套配额与平局）上，算法
输出均通过无阻挡对证书，且均落在穷举得到的稳定方案集合内；10 申请人 ×
6 机构上限实例求解并验证稳定。`npm run demo` 演示 6 申请人 × 2 机构含嵌套
配额的求解（238 个可行分配中唯一稳定解）、撤回单个申请与申请人退出后的
重算，均输出逐对证书。
