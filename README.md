# jointsim

单领导者复制日志模拟器，实现 Raft 风格的联合共识（joint consensus）成员变更：

- **先联合配置**：`ChangeMembership` 先追加联合配置条目（old+new），联合配置提交后才追加最终配置条目。
- **双多数提交**：联合阶段（含最终配置条目自身）的每次提交都必须同时获得旧集多数与新集多数；最终配置提交后只用新集。
- **幂等**：重复的成员变更请求（进行中或已完成）是无副作用的 no-op；冲突目标被拒绝；重复投递的日志条目按 (index, term) 幂等去重。
- **故障轨迹检查**：`CheckTrace` 校验轨迹中每条提交都带有效仲裁证书，且未提交的新集绝不可单独推进（最终配置提交前，每张证书必须覆盖最近稳定配置的多数）。
- **仲裁证书**：每条提交产生 `Certificate`（配置 + 投票成员），可独立 `Verify()`。

## 运行

```sh
go test ./...
go run ./cmd/jointsim   # 打印每条提交的仲裁证书并校验轨迹
```

## 结构

- `config.go` — 配置（简单/联合）、法定人数判定、仲裁证书
- `node.go` — 日志条目与幂等追加
- `sim.go` — 模拟器：消息队列、故障注入接口、提交推进、成员变更状态机
- `checker.go` — 轨迹安全检查器
- `sim_test.go` / `checker_test.go` — 联合提交、幂等、分区故障、证书输出与检查器正反向用例
