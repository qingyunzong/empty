# sched — 单执行器单位任务调度 CLI

至多 18 个单位时长任务，每个任务有释放时刻、截止时刻与收益。
选择总收益最大的可行子集；收益并列时取任务 ID 执行序列字典序最小者。
任务 `i` 占用整数时槽 `t`，需满足 `release <= t && t+1 <= deadline`。

## 用法

从标准输入读取命令脚本（`#` 为注释）：

    go run . <<EOF
    add 1 0 2 10
    add 2 0 2 9
    add 3 1 3 8
    solve
    undo 1
    solve
    verify
    EOF

命令：

- `add <id> <release> <deadline> <profit>` — 添加任务
- `remove <id>` / `undo [id]` — 撤销任务（无参 `undo` 撤销最后添加者），随后 `solve` 重算
- `list` — 列出当前任务
- `solve` — 输出最优调度与时间证书（时槽分配 + 可行性/最优性校验）
- `verify` — 与穷举所有序列的暴力解对照（限 n ≤ 12）

## 算法

- 可行性：按截止时刻贪心分配最早空闲时槽（凸二分图匹配，正确性由交换论证保证）。
- 最优收益：枚举全部 2^n 个子集（n ≤ 18），取可行且收益最大者。
- 并列打破：对每个最优子集用"最小可行前缀"贪心构造字典序最小执行序列，再取全局最小。
- `sched.BruteForce` 枚举所有子集的所有排列作为小实例对照预言机。
