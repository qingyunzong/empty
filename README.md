# maintsched — 维修排程 CLI

为至多 16 项维修任务选择候选半开窗口，最小化总费用（安排费用 + 放弃罚费）。

## 问题模型

- 每项任务有若干候选**半开窗口** `[start, end)`，选某窗口即付其费用；首尾相接不算重叠。
- **依赖**：任务可声明前项 `depends_on`；前项必须被安排且其窗口结束时间不晚于本任务窗口开始时间。前项被放弃时，后项必须放弃。
- **共享设备**：同一设备上的任务窗口不得重叠。
- **放弃**：任何任务可放弃，计入其罚费 `penalty`。
- 目标：总费用 = Σ 所选窗口费用 + Σ 放弃罚费，求最小。

## 输入格式（JSON）

```json
{
  "jobs": [
    {"id": "A", "equipment": "crane", "depends_on": [], "penalty": 20,
     "windows": [{"start": 0, "end": 4, "cost": 5}]}
  ]
}
```

## 用法

```sh
go run . -input example.json          # 求解并输出各项安排与冲突解释
go run . -input example.json -verify  # 附加完整枚举，验证最优性（限 12 项以内）
cat example.json | go run .           # 标准输入
```

输出每项任务的安排（设备、窗口、费用）或放弃原因；对被放弃的任务逐窗口给出冲突解释
（前项被放弃 / 前项未完成 / 共享设备重叠 / 费用不低于罚费）。

## 算法

- 主求解器 `Solve`：按拓扑序深度优先搜索 + 分支定界。下界为每个未处理任务
  `min(最便宜窗口, 罚费)` 的后缀和；并用贪心可行解与"全部放弃"收紧上界。
- 验证器 `BruteForce`：不做任何剪枝的完整枚举，供小数据对照。
- `CheckSolution`：独立校验解的依赖、设备不重叠与费用一致性。
