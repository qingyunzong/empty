# lr1-conflict-cli

规范 LR(1) 语法分析 CLI：读入至多 20 条产生式的上下文无关文法，构造**规范 LR(1)** 状态机，
报告移入-归约（及归约-归约）冲突，并给出从初始状态到冲突状态的**最短符号路径**；
对小文法通过**枚举可行前缀**独立核对每个状态的 LR(1) 项目集。

仅使用 TypeScript + Node.js 内置库（`node:fs`、`node:test`、`node:assert` 等），无任何 npm 依赖。

## 构建与测试

```sh
npm run build   # 用全局 tsc 编译到 dist/
npm test        # 编译并运行 node --test（结果见 RESULTS.md）
```

## 使用

```sh
node dist/src/cli.js [选项] [文法文件]   # 省略文件或传 "-" 时从标准输入读取
```

选项：

- `--states`：打印全部规范 LR(1) 状态及项目集
- `--lalr`：打印 LALR(1) 合并对照的详细信息
- `--verify=N`：前缀枚举核对的最大前缀长度（默认 4）
- `--no-verify`：跳过前缀枚举核对
- `--help`：显示帮助

文法格式：每行一条规则 `LHS -> alt1 | alt2 | ...`；符号以空白分隔；`#` 之后为注释；
空右部或 `ε`/`eps`/`epsilon` 表示空产生式；出现在左部的符号为非终结符；
开始符号为第一条规则的左部；产生式总数（每个候选式单独计）至多 20 条。

## 设计要点

- **规范 LR(1)，不做状态合并**（`src/lr1.ts`）：按完整 LR(1) 项目集（含向前看符号）
  构造闭包与转移，因此 LALR 合并才可能引入的冲突天然不会被算作原文法冲突。
  另提供 `analyzeLalr` 对照：按 LR(0) 核心合并状态后重新检测冲突，
  仅由合并引入的冲突会标注 `合并引入（非原文法冲突）`，不计入原文法冲突报告。
- **冲突报告**：对每个冲突给出状态编号、冲突类型、终结符、移入/归约动作、相关项目，
  以及用 BFS 求得的初始状态到该状态的**最短符号路径**（按符号数计）和状态到达链。
- **前缀枚举核对**（`src/verify.ts`）：依据有效项目的定义
  `S' ⇒* δA a w ⇒ δαβ a w`（γ = δα），以最右推导枚举句型；
  由于 `a` 之后全是终结符且不再参与推导，句型只需记录到最右非终结符为止、
  并保留其后首个终结符作为向前看符号。目标句型（长度 ≤ N+1）的推导中间形态
  可能更长，故采用自适应加深：逐步放大中间形态长度上界，连续两轮项目集不变即
  判定收敛；达到理论界限仍未收敛则按界限停机；句型数超预算则报告截断（不完备）。
  最后将每个可行前缀（长度 ≤ N）的枚举项目集与自动机中沿该前缀到达的状态逐一比对。

## 目录

- `src/grammar.ts`：文法解析、FIRST 集
- `src/lr1.ts`：规范 LR(1) 构造、冲突检测、最短路径、LALR 对照
- `src/verify.ts`：可行前缀枚举核对
- `src/cli.ts`：命令行入口（`runCli` 可在进程内调用，便于测试）
- `test/`：`node:test` 测试
- `examples/`：示例文法
- `RESULTS.md`：实际测试与运行结果
