# 消息帧的通道正文剩余量

消息采集把多个通道的正文帧交错送来，剩余字节若记在连接上而不是通道上，后一个通道会提前结束。实现可导入的Go组件，供消息采集调用，不建立连接。帧由1字节类型、大端uint16通道、大端uint32长度、载荷和结尾字节0xCE组成。长度不含结尾字节，大于宿主maxFrame时在4字节可读后拒绝，不按声明分配。类型8是心跳，通道和长度都必须为0。类型1是方法，载荷以前两个大端uint16类别和方法开始，其余参数原样保留。类型2是内容头，载荷是大端uint16类别、必须为0的uint16权重、大端uint64正文总长，以及至少2字节属性标志；同一通道不能已有未完成正文。类型3是正文，载荷长度必须不超过该通道剩余正文，扣减后剩余为0才允许下一个内容头。心跳和方法可以插在正文之间，但不得属于另一个尚未完成的内容头以外的新内容头。通道0只允许心跳。缺少0xCE、类型不是1、2、3、8，或正文未完就遇到新的类型2，都失败。Push可停在帧中间；Finish时仍有未完成帧或正文则失败。失败停止组件，已交付帧保留。测试独立组帧，覆盖两通道交错、心跳插入正文、剩余多1字节、权重非0和帧被切开。期望帧不得调用被测组件生成。
