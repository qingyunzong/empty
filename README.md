# lr1-conflict-cli

语法分析 CLI：读入至多 20 条产生式，构建**规范 LR(1)** 自动机，报告移入-归约冲突，
并给出到每个冲突状态的**最短符号路径**。LALR(1) 同心状态合并引入的冲突单独报告，
**不计入**文法本身的冲突。支持对小文法做**前缀枚举核对**项目集（`--verify`）。

仅使用 TypeScript + Node.js 内置库，无任何运行时依赖。

## 输入格式

- 每行一条规则：`LHS -> rhs1 | rhs2 | ...`（也支持 `→`、`::=`）
- 符号以空白分隔；`#` 之后为注释
- 空候选分支或 `eps` / `ε` 表示 ε 产生式
- 每个候选分支计 1 条产生式，总计超过 20 条则报错退出（退出码 2）
- 第一条规则的左部为开始符号，自动增广

## 使用

```sh
npm run build
node dist/src/cli.js examples/else.txt          # 从文件读取
node dist/src/cli.js --verify < examples/else.txt  # 标准输入 + 前缀枚举核对
```

输出示例（`examples/else.txt`，悬挂 else 文法）：

```
规范 LR(1) 自动机：12 个状态
发现 1 个移入-归约冲突，0 个归约-归约冲突：
状态 8，前瞻符号 'e'：移入-归约冲突
  移入 -> 状态 10
  归约 S -> i S
  到冲突状态的最短符号路径：i i S
LALR(1) 检查：合并为 7 个状态，未引入新冲突。
```

退出码：无冲突 0；存在（规范 LR(1)）冲突 1；输入/文法错误 2。

## 实现要点

- `src/grammar.ts`：文法解析、FIRST 集输入格式与 20 条上限检查
- `src/lr1.ts`：FIRST 集、闭包/转移、规范 LR(1) 自动机、冲突检测、
  BFS 最短符号路径、LALR(1) 同心合并分析（合并引入的冲突单独列出）
- `src/verify.ts`：独立核对——蛮力枚举有界最右推导，按定义
  `[A→α·β, a]` 对前缀 `γ=δα` 有效当且仅当 `S' ⇒* δAaw ⇒ δαβaw`，
  与自动机沿前缀到达的项目集逐一比较
- `src/cli.ts`：命令行入口
