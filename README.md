# reactive-state

响应式状态库（TypeScript + Node.js 内置库，零运行时依赖）。

## 核心语义

主实现 `src/reactive.ts` 采用**读取事务 + 结束时一次性提交**的依赖管理：

1. **读取事务结束时一次登记依赖**：重算期间只把读到的依赖收集到临时集合，
   事务成功结束时才一次性提交（退订不再读取的、订阅新读取的）。
   事务进行中不产生任何订阅副作用；同一依赖在一次事务中读多次只登记一次。
2. **计算抛错不改变旧依赖**：计算函数抛错时丢弃本次收集结果，旧依赖与旧缓存值
   原样保留（无任何退订发生），错误被缓存并在 `get()` 时重抛；依赖变化后可正常恢复。
3. **销毁与重算交错不留订阅**：重算期间（含计算函数内部自我销毁）若节点被销毁，
   提交阶段直接放弃；flush 队列中被销毁的 effect 会被跳过；销毁后再读取只做
   一次性求值，不登记订阅。
4. **动态条件切换清理依赖**：`cond ? a : b` 切换分支后，不再读取的源在提交时
   被退订，之后修改它不再触发重算。

## 对照实现

- `src/refcount.ts`（引用计数）：读取时立即订阅、重算开始先退订全部旧依赖。
  对照表明其固有缺陷：抛错丢失旧依赖、销毁交错留下泄漏订阅、依赖不变的重算
  也产生成对的退订/订阅（churn）。
- `src/full-recompute.ts`（全量重算）：不做依赖跟踪，任何源变化重跑整个链路。

## API

```ts
import { source, computed, effect, batch } from "./src/index.js";

const a = source(1);
const b = source(2);
const sum = computed(() => a.get() + b.get());
const stop = effect(() => console.log(sum.get()));
batch(() => { a.set(10); b.set(20); }); // effect 只运行一次
stop.dispose();
```

npm test    # tsc 编译 + node --test（Node.js 内置测试运行器）

### 实际运行结果（2026-10-05，Node v22.22.1，tsc 7.0.2）

```
# tests 5
# pass 5
# fail 0
```

5 个测试文件全部通过：

- `test/transaction-commit.test.ts` — 事务期间不登记、结束时一次登记；
  同一事务多次读取只登记一次；依赖不变的重算零订阅操作；菱形依赖无重复重算。
- `test/error-keeps-deps.test.ts` — 抛错后旧依赖保留（0 次退订）、可恢复；
  对照：引用计数实现抛错后旧依赖丢失。
- `test/dispose-interleave.test.ts` — 计算中自我销毁不留订阅；flush 中销毁
  待运行 effect 被跳过；销毁后读取为一次性求值；对照：引用计数实现泄漏订阅。
- `test/conditional-switch.test.ts` — 条件切换退订旧分支、修改旧分支不再触发；
  batch 内多次 set 只运行一次；嵌套 computed 沿链清理。
- `test/comparison.test.ts` — 同一场景三实现对照（实际输出）：

```
场景：cond?a:b → *2 → effect；a 改 3 次、切换 cond、b 改 1 次、
      切换后再改 a 1 次、无关源 noise 改 2 次。

| 实现             | c 重算 | d 重算 | effect 运行 | 订阅操作 | 退订操作 |
| ---------------- | ------ | ------ | ----------- | -------- | -------- |
| 主库（事务提交） | 6      | 6      | 6           | 5        | 2        |
| 引用计数         | 6      | 6      | 6           | 24       | 21       |
| 全量重算         | 9      | 9      | 9           | （无跟踪） | （无跟踪） |
```

主库按需重算且订阅操作最少；引用计数重算次数相同但订阅 churn 约 5 倍；
全量重算被无关源惊动，多跑 50% 的计算。
