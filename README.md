分布式键值存储需要供请求路径调用的Go仲裁组件，按版本向量合并并发写，R/W仲裁响应后继续有限读修复。超时副本迟到不能覆盖新版本，删除墓碑保留到安全水位。用分区与恢复序列验证返回兄弟集合和最终副本收敛。

## 实现结构

- `clock.go`：版本向量 `VClock`，分量最大值合并、因果支配 `Descends`、并发判定。
- `version.go`：带墓碑的 `Version` 与兄弟集合合并 `MergeVersions`；祖先版本被剪枝、并发版本保留为兄弟、同时钟墓碑压过活值；`Visible` 对请求路径隐藏墓碑。
- `replica.go`：单副本本地存储。每次写入走向量时钟合并，迟到的祖先版本无法覆盖新版本；维护安全水位 `watermark` 与每键 `gcBarrier`，墓碑在水位到达前保留，GC 后用屏障阻止旧值复活。
- `transport.go`：进程内 `Transport`，按调用方/目标的分区分组模拟网络分裂与按副本延迟，分区内 RPC 直接失败。
- `coordinator.go`：请求路径仲裁组件。
  - `Get`：并发 fan-out，达到 R 即返回合并后的活兄弟集合，随后在 `RepairTimeout`/`MaxRepair` 预算内做后台读修复（应答节点本身可能陈旧，不跳过）。
  - `Put`/`Delete`：先做 R 仲裁读取得因果基线，再在本节点分量上自增生成后代版本，写满 W 即返回，剩余副本由受限后台写修复补齐；`Delete` 写入带删除纪元的墓碑。
  - `Compact`：全副本推进安全水位并回收墓碑；任一副本不可达即失败且不移动水位，保证墓碑保留到安全水位。

## 关键不变量

- 迟到/超时副本带回的旧时钟在 `Replica.Apply` 与 `MergeVersions` 两层都被剪枝，永不覆盖新版本。
- 并发写返回完整兄弟集合（多活值），由后代写解析后经读/写修复收敛到单值。
- 墓碑在 `DelEpoch <= watermark` 前物理保留；回收后其时钟并入 GC 屏障，被屏障支配的旧值写入被拒绝。

## 验证

```
go test -race ./...
```

覆盖：向量时钟与合并规则、陈旧写拒绝、读修复收敛、N=4/R=W=2 双分区并发写→恢复后兄弟集合→后代写全副本收敛、慢副本迟到不回退、墓碑保留/全集群 Compact/复活防护、多数派分区下仲裁不可用、失败路径无 goroutine 泄漏。
